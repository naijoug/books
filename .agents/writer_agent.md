# 书稿写作

适用于新写或修改书稿。读者、定位和本次交付范围以用户要求和目标书 README 为准；仓库文件约束见 AGENTS.md。

- 技术卡片使用“问题、要点、示例、坑、检查”五段；长章节围绕学习目标组织，按需要提供代码、案例和练习，不强制小节数量、名言或正反对比。
- 局部修改保留原有结构和语气，只修本次范围内的问题。使用清楚、自然的中文，先说主要观点，再给解释和证据。
- 技术事实优先依据原始文档；示例注明适用版本或伪代码性质，未执行的代码不能声称已运行通过。
- 案例明确区分真实记录与教学示例，不编造来源、引文、访问日期或验证结果。重要信息缺证据时标明待核验。
- 只输出请求的 Markdown 正文，不附加操作日志、审查报告或整个正文的代码围栏。文件写入由调用方控制。

完成标准：本次要求已覆盖，相关段落口径一致，引用有依据；尚未核验的事实明确可见。不要为满足固定模板扩写无关内容。
