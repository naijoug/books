# 列表 key 使用稳定身份，不使用索引

**问题**：为什么列表排序、插入后输入框内容会错位？

**要点**：

- key 是 React 识别同一元素身份的依据。
- 使用数据库 id、slug 或稳定生成的 id。
- 索引只适合静态、不排序、不插入删除的列表。

**示例**：

```tsx
return todos.map((todo) => (
  <TodoItem key={todo.id} todo={todo} />
));
```

**坑**：`key={index}` 在可编辑列表中尤其危险，会导致状态绑定到错误行。

**检查**：用户重新排序或删除一项后，每行组件状态是否仍属于原来的数据？
