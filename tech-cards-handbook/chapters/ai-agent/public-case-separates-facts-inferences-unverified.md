# 公开案例先分事实、推断和未验证，不要把审查记录直接写成结论

## 问题

AI 编程审查或 Agent 工作流复盘很容易从“我看到了这些证据”滑到“所以客户一定获得了这些收益”。公开案例一旦把事实、推断和未验证风险混在一起，短期看更像战报，长期会损害可信度：读者无法判断哪些结论能复用，哪些只是作者的解释。

公开案例不是把内部审查记录润色成故事，而是把 claim 按证据强度分层：事实可以进入正文，推断必须标明依据，未验证项要保留为下一步证据需求。

## 要点

写公开案例前，先给每个 claim 打标签：

| 标签 | 含义 | 公开写法 |
|---|---|---|
| `Fact` | 有命令、diff、日志、PR 评论、用户原话或授权记录支撑 | 直接写，但要脱敏和压缩 |
| `Inference` | 基于事实作出的风险判断或优先级判断 | 写成“因此我们判断 / 优先检查”，并指向依据 |
| `Unverified` | 还没有证据，或只在局部环境观察到 | 放进 `Unverified` / `Next evidence needed` |
| `Private` | 有证据但不适合公开 | 只写公共安全摘要，删除可识别细节 |
| `Stop` | 授权、合规、密钥、生产权限或证据链不足 | 暂停发布，降级为方法样板 |

最小流程：

1. **先列 claim，不先写故事**：把案例里想表达的每句话拆成 claim，再逐条找证据。
2. **事实和推断分段**：事实回答“发生了什么”，推断回答“为什么先查这里”。
3. **未验证项不要消失**：读者最需要知道边界；把缺口写成 `Next evidence needed`，而不是省略。
4. **公开版本只保留可公开证据**：私有证据可以支撑内部判断，但公开稿只写脱敏摘要。

## 示例

内部审查记录可能长这样：

```text
Focused reducer test failed after AI-generated state refactor.
The branch mixing empty state and error state looks risky.
Typecheck passed.
No browser smoke was executed.
Customer said the report was useful.
```

不要直接改写成：

```text
我们发现 AI 重构导致 UI 错误，并帮助客户显著提升质量。
```

更安全的公开案例写法是：

```text
Fact: focused reducer test 暴露了 error branch 与 empty state 的分支混用；typecheck 通过。
Inference: 因为风险集中在状态语义而不是类型错误，本轮优先建议补 reducer 分支测试，再做最小 UI smoke。
Unverified: 未执行浏览器 smoke，未观察生产数据，也没有足够证据声称“显著提升质量”。
Next evidence needed: 补一条错误态 UI smoke，或记录使用方按建议修改后的验证结果。
```

这段看起来没有“战报”刺激，但它让读者知道哪些可以相信、哪些还不能相信。

## 坑

- **把推断写成事实**：例如把“可能影响错误态渲染”写成“已经导致线上故障”。
- **删除未验证项**：省略 `Unverified` 会让案例更流畅，但也会隐藏方法边界。
- **用客户反馈替代技术证据**：用户说“有用”是反馈事实，不等于修复已经上线或指标已经改善。
- **把脱敏当作自由改编**：可以替换名称和路径，不能改变验证结果、失败原因和因果顺序。
- **为了转化补收益数字**：没有来源的百分比、节省小时数和事故率，比没有数字更危险。

## 检查

发布前用这 6 个问题收口：

1. 每个核心 claim 是否已标成 `Fact`、`Inference`、`Unverified`、`Private` 或 `Stop`？
2. `Fact` 是否能指向至少一种证据，而不是来自 AI 总结或记忆印象？
3. `Inference` 是否写明依据和不确定性，没有伪装成确定结果？
4. `Unverified` 是否保留在公开稿或转成 `Next evidence needed`？
5. `Private` 信息是否只留下公共安全摘要，没有泄露客户、仓库、代码或权限边界？
6. 如果出现 `Stop`，是否真的停止发布，而不是继续包装成匿名案例？

最后把发布动作落到 `Continue / Narrow / Stop`：证据充分就继续发布；证据局部不足就缩小为方法样板；授权、合规或证据链断裂就停止。

公开案例的可信度来自边界，不来自戏剧性。先分事实、推断和未验证，再决定能否进入正文。
