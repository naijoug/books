# 上下文预算是一种资源，不要把所有历史都塞进提示

**问题**：Agent 有更长上下文窗口后，为什么仍然需要控制输入内容？

**要点**：

- 上下文越长，模型越容易被旧目标、过期状态和低价值噪音牵引。
- 预算应该优先给当前任务、权威状态、工具结果、失败证据和安全边界。
- 旧 notebook、历史计划和参考资料要先摘要、筛选，再进入本轮运行上下文。

**示例**：

```text
必须加载：当前任务、当天 notebook 最新段落、相关 repo 的 git status、目标文件片段
按需加载：上一轮详细 diff、参考资料、历史讨论
不要加载：已完成的旧计划、无关 repo 的长日志、未验证的猜测
```

**坑**：把“更多上下文”误当成“更可靠”，会让 Agent 在旧指令、旧计划和当前事实之间摇摆。

**反例 / 修正做法**：

- 反例：为了让 Agent “充分理解项目”，启动时一次性塞入最近 30 次 `summaries/hermes/YYYY-MM-DD.md`、所有 `docs` 脏改动列表、整本书稿目录和上一轮未验证猜测。结果模型把两周前的计划当成当前接力点，忽略本轮 `git status --short`，还把无关 repo 的失败当成本轮阻塞。
- 修正：先定义本轮问题，再按证据优先级装载上下文：当前指令、当天 notebook 最后一段、相关 repo 状态、目标文件和最近一次失败输出。历史 notebook 只提取“上一段接力点”和“长期约束”，无关 repo 只记录“存在既有脏改动，暂不混入”。如果仍超预算，优先保留可验证事实和停止条件，删掉叙事性总结。

**检查**：进入模型上下文的每一段材料，都应该能回答“本轮决策是否需要它、它是否仍然新鲜、它来自哪个权威来源”。
