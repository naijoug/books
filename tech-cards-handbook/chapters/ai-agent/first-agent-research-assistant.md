# 第一个 Agent 先做研究助手，不要一开始做全能助手

**问题**：初学者应该从什么 Agent 形态开始练习？

**要点**：

- 研究助手范围清楚：搜索、总结、保存笔记。
- 工具数量少，便于观察模型如何选择下一步。
- 输出物是 Markdown 笔记，容易人工检查。

**示例**：

```text
目标：研究一个主题并保存笔记
工具：Search(topic)、SaveNote(markdown)
停止：笔记保存成功，或连续两次工具失败
```

**坑**：一开始就加入浏览器、文件系统、数据库、消息发送等大量工具，会让问题定位非常困难。

**反例 / 修正做法**：

- 反例：第一个练习项目就做“全能个人助理”，同时接入浏览器、邮箱、日历、文件系统、数据库和支付接口。Agent 失败时，只能看到“没有完成任务”，却分不清是搜索结果不足、工具 schema 不清、权限被拒绝，还是目标本身太大。
- 修正：先做只读研究助手：输入一个主题，最多调用 `Search` 3 次，把来源、要点、未确认问题和下一步建议保存为一篇 Markdown；写入工具只允许保存到 `docs/research-notes/`，不发送消息、不改数据库、不触发外部交易。等搜索、总结、保存和失败出口都可观察后，再逐步增加一个新工具。

**检查**：如果 Agent 出错，你能否在 5 分钟内判断是模型判断错、工具实现错，还是目标描述错？不能的话，范围还太大。
