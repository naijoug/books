# Agent 必须有迭代上限和失败出口

**问题**：如何避免 Agent 卡在解析错误、工具失败或目标不清的循环里？

**要点**：

- 设置最大迭代次数和最大运行时间。
- 工具失败要返回可读错误，而不是让异常完全吞没上下文。
- 连续失败时应总结当前状态并停止，而不是无限重试。

**示例**：

```text
max_iterations: 5
on_tool_error: 记录工具名、输入、错误摘要
stop_after: 连续 2 次同类失败
```

**坑**：把 `handle_parsing_errors` 当成万能兜底，只会隐藏 prompt、工具 schema 或模型输出格式的问题。

**反例 / 修正做法**：

反例：Agent 连续 5 次调用 `SearchDocs` 都返回 `timeout`，仍然继续改写 query、追加同义词并报告“正在努力检索”，最终既没有可验证结果，也没有说明失败卡在哪里。

修正做法：第 2 次同类 `timeout` 后立即停止自动重试，输出失败状态：已尝试的 query、失败工具名、错误摘要、最后一次可观察返回值、尚未完成的用户目标，以及下一步证据命令（例如先用 `search_files` 限定目录，或改为读取已知索引文件）。如果失败来自工具 schema 或权限边界，不再换 prompt 硬跑，而是把 schema/权限缺口写入后续接力。

**检查**：故意让一个工具失败，Agent 是否会给出清楚的失败原因和下一步，而不是继续空转？
