# 双向导航闭合发布资产，不要只从 README 单向指路

## 问题

Agent 连续补书稿、清单、样例、主持脚本或发布模板时，常会先在根 README 做一条“推荐阅读路径”。这能让新读者从入口页顺利进入材料，但还不够：真实使用者往往是从正文、附录、样例或搜索结果直接落到某个页面。如果这些下游页面没有反向指向入口表、术语表、字段来源和交接目标，材料会变成一组孤岛。

这张卡解决的问题是：当一次改动新增或强化了多个发布资产时，如何用双向导航把“入口 → 正文 → 模板 → 样例 → 交接”闭合，而不是只在首页堆一个总目录。

## 要点

1. **先定义入口问题，而不是入口文件**：导航表的第一列应是“我现在要判断什么”，例如灰度范围、`warn` / `block`、回滚 owner、下一次复审，而不是“先读 A 再读 B”。
2. **每个下游页面都要知道上游来源**：附录、样例和主持脚本开头要说明字段来自哪一章、哪张表或哪份发布报告，避免读者复制模板后不知道证据从哪里来。
3. **每个正文段落都要知道下游产物**：正文提到工具网关、安全回归、trace、灰度或回滚时，要指向会被填写的清单字段、门禁样例或会后交接字段。
4. **模板之间要做邻近同步**：新增清单字段时，同步检查填写样例、主持脚本、会后交接和索引描述；不要只让一个入口拥有最新字段。
5. **术语表需要正反两条路**：README 里的术语表负责统一口径，正文和模板里的争议点要能反链它；否则读者仍会在现场把“工具网关”写成“权限网关已完成”。
6. **导航验证不等于链接存在**：链接 checker 只能证明目标文件存在；人工复核还要确认链接回答了“我为什么此刻要跳过去”。

## 示例

一次围绕 Agent 上线评审的材料闭合，可以按下面顺序补导航，而不是一次性新增更多表单：

```text
入口表：
- README：评审问题 -> 先看章节 -> 使用材料 -> 最小产物

正文到模板：
- 第 7 章工具安全元数据 -> 附录 A 工具网关字段 -> 附录 B warn/block 判断
- 第 8 章评估报告 -> 附录 A 评估门禁 -> 附录 C 评审会追问
- 第 9 章发布报告 -> 附录 C allowed_scope / rollback_runbook / next_review_trigger
- 第 10 章服务端控制点 -> README 术语表 -> 附录 A/B 安全门禁

模板反向来源：
- 附录 A：现场争议先填哪块清单，并回到第 7-10 章找证据
- 附录 B：说明哪些字段来自附录 A，哪些结论不能把 block 包装成 warn
- 附录 C：说明会后交接字段来自第 9 章发布报告
```

如果本轮只做 30 分钟小改，不要新增第四份模板。先抽一条真实路径做 proof：

```text
读者从“回滚 owner 不清楚”进入 README
-> 跳到第 9 章 rollback 字段
-> 填附录 A 的监控/止损区域
-> 用附录 C 写 rollback_runbook 和 next_review_trigger
-> 最终报告能说清下一位值班同学第一条动作
```

这条路径走通后，再考虑是否需要新样本；走不通时，优先补双向导航或字段来源，而不是扩表面。

## 坑

- **只更新总 README**：首页路径看起来完整，但读者从搜索结果进入附录时看不到字段来源。
- **只补更多附录**：材料数量增加，现场仍不知道该复制哪一份、哪一份是最终交接产物。
- **把链接存在当成使用闭环**：Markdown 链接都能打开，不代表读者知道为什么此刻要跳转。
- **术语表只放入口页**：正文仍使用旧词，评审现场继续出现“权限网关”“小流量灰度”“trace 已有”这类含糊判断。
- **样例和模板字段不同步**：空白清单新增了 `next_review_trigger`，填写样例或主持脚本仍只写“后续观察”。
- **没有最小路径 proof**：一次改动声称“闭环”，但没有从一个真实争议走到最终交接字段。

## 检查

提交多材料发布资产前，逐项确认：

- README 或入口页是否按“问题 / 角色 / 当前风险”组织，而不是只列文件？
- 正文中每个关键判断是否指向要填写的模板字段或交接产物？
- 附录、样例和主持脚本是否说明字段来源和上游证据位置？
- 新增字段是否同步到空白模板、填写样例、主持脚本、目录索引和最终报告口径？
- 术语表是否既能从入口页进入，也能从正文争议点反向找到？
- 是否至少手工走通一条“真实争议 -> 正文证据 -> 模板字段 -> 交接动作”的最小路径？
- 最终 notebook 是否写清本轮验证的是链接存在、字段关键词，还是完整阅读路径？
