# 新表面要有复用证明，不要把同一经验连续扩成近重复资产

**问题**：Agent 从一次心跳里提取出有价值的经验后，为什么容易连续写出 `docs/`、`skills/`、`books/` 三四份相似材料，却没有让下一轮执行更快、更准或更容易验证？

**要点**：

- 新增表面前先写出 `reuse proof`：下一轮会在哪个入口、以什么命令、模板或判断表复用它。
- 同一经验最多先落两个互补表面：一个面向读者理解，一个面向执行复用；第三个表面必须证明前两个无法承载当前用例。
- 如果上一轮刚把规则写进 skill，本轮默认要使用它完成项目、书稿、样本或收入实验，而不是再写一篇解释同一规则的文档。
- 复用证明要可验证：入口链接、决策字段、命令输出、样例填表或后续任务的第一条动作，不能只写“以后可复用”。
- 找不到复用证明时，把信号留在 notebook 的后续接力里，等第二个真实用例出现再资产化。

**示例**：

```text
信号：连续两轮都在提醒“不要把 worklog extraction 继续写成相邻材料”。
已有表面：
- docs：解释为什么工作日志可以提取成资产。
- skill reference：让 cron 在候选选择阶段使用 decision gate。

候选新表面：再写一篇同主题 blog。
reuse proof 检查：
- 下一轮是否会通过它执行一个不同动作？否。
- 是否提供 docs/skill 没有的模板、命令或样例？否。
- 是否解决新的读者/执行者场景？否。

决策：Stop。下一轮改为使用 skill reference 回看 notebook，或切换到一个 clean path 的真实项目小修复。
```

**反例 / 修正做法**：

```text
反例：
- 第 1 轮写 docs 卡片：工作日志资产提取器。
- 第 2 轮写 skill reference：工作日志资产提取器。
- 第 3 轮又写书稿卡片：工作日志资产提取器。
- 第 4 轮继续写样本包：工作日志资产提取器。

修正：
- 第 3 轮不再扩同名资产，而是拿 skill reference 做一次真实选择：
  - 找最近 3 条 notebook 的重复 stop rule；
  - 判断是否已有执行入口；
  - 只在缺少执行入口时新增资产。
- 如果缺的是“停止扩表面”的原则，卡片标题必须换成新的决策问题，并写清它如何防止继续扩写。
```

**坑**：

- 把“同一内容放到不同目录”误当成资产飞轮；真正的飞轮要求每个表面承担不同用途。
- 因为某个目录当前 clean，就机械新增文件，忽略是否会减少下一轮判断成本。
- 用“可验证”替代“值得做”：链接、索引和格式都能通过，但读者仍然得不到新的行动入口。
- 在无人值守 cron 中为了制造提交而新增近重复材料，导致 notebook 看起来忙碌，项目却没有推进。

**检查**：新增任何第三个同主题表面前，先回答三句：已有表面分别服务谁？新表面比已有表面多提供哪一个可执行入口？下一轮第一条动作是否会因为它而改变？如果答不上来，就停止新增表面，转为使用已有资产完成一个真实小任务。
