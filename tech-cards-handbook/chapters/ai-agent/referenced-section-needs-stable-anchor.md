# 被引用的页面区域需要稳定锚点，不要只在文案里说“上方/下方”

**问题**：Agent 在页面、文档或交接记录里写了“见上方导读”“回到检查清单”“按下面模板填写”这类引用时，如何避免读者只能靠滚动寻找，而下一轮也无法测试这个结构是否还存在？

**要点**：

- 只要某段文案要求读者跳到另一个页面区域，就给目标区域一个稳定 `id` 或明确标题锚点；不要只依赖“上方”“下方”“前面”这类位置词。
- 链接文字要说明动作，例如“回到导读”“查看验收标准”，而不是只写“这里”；这样读者和测试都能理解跳转意图。
- 生成型页面要在生成脚本里维护锚点和跳转链接，不要只手改生成后的 HTML，否则下一次渲染会丢失结构。
- 测试至少检查两件事：目标锚点存在，引用链接指向该锚点；如果是多个 CTA 复用同一入口，还要检查它们指向一致。
- 不要为所有标题机械加锚点；优先处理被 CTA、目录、交接说明或外部链接引用的区域。

**示例**：

```html
<section id="reading-guide" class="reading-guide">
  <h2>从哪一期开始读</h2>
  <p>按最新、创刊、精选三条路径选择一篇。</p>
</section>

<section class="subscribe-cta">
  <p>还没决定是否订阅？先 <a href="#reading-guide">回到导读</a> 读一篇。</p>
</section>
```

对应的轻量检查可以只验证结构契约：

```python
html = page.read_text(encoding="utf-8")
assert 'id="reading-guide"' in html
assert 'href="#reading-guide"' in html
```

如果页面由脚本生成，把 `id="reading-guide"` 和 `href="#reading-guide"` 同时放进生成函数和单测里；不要在生成物里补完锚点后忘记修改脚本。

**坑**：

- 文案写“按上方导读”，但没有 `href`，移动端读者读到底部后只能手动回滚。
- 只给生成后的 HTML 加锚点，下一次运行渲染脚本后结构消失。
- 测试只断言文案包含“导读”，没有断言 `id` 与 `href` 是否配对。
- 给每个标题都加随机或自动生成锚点，后续改标题导致外部链接失效。
- 最终报告说“补了导读链接”，但没有说明验证命令覆盖了目标锚点和引用链接两端。

**检查**：看到“上方/下方/前面/后面/参考某段”这类跨区域引用时，先问：目标区域是否有稳定锚点？引用处是否是可点击链接？生成脚本和生成物是否一致？测试是否能在锚点缺失或 `href` 拼错时失败？如果四个问题任一答案为否，本轮应先补结构，再扩写文案。
