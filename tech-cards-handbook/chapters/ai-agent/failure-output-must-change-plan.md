# 失败输出要改变计划，不要当作背景噪音

**问题**：Agent 已经看到命令失败、工作区 dirty、测试不通过或搜索结果缺失时，如何避免继续按原计划推进，最后把失败信号包装成顺利完成？

**要点**：

- 失败输出不是“记录一下就算了”，它必须改变至少一项：范围、顺序、目标或交接。
- 先判断失败类型：环境失败、前置条件失败、验证失败、边界失败、信息缺口；不同类型对应不同调整。
- 如果失败来自非本轮改动或边界不清，优先缩小到原任务内可独立验证的部分，不要用全量命令继续制造噪音。
- 如果失败来自本轮改动，先修复或降级声明；不能验证通过的内容必须进入显式交接。
- 最终报告要写出“失败输出如何改变了本轮计划”，而不只是写“遇到失败但已处理”。
- 配套收尾核对可用 [`../../samples/ai-agent-failure-absorption-one-pager.md`](../../samples/ai-agent-failure-absorption-one-pager.md)：先把失败写成“信号 -> 影响 -> 证据位置”，再选择范围缩小、顺序变更、目标切换或交接改写。

**示例**：

```text
原计划：
- 继续修改 loom 的日志面板。

工具输出：
- git status 显示 loom 已有多处非本轮 UI/设计文件改动。

计划调整：
- Target：保留 loom 日志面板目标，先确认 diff 和授权。
- Scope：只暂停与未知改动冲突的部分，继续不受影响的测试或修复。
- Evidence：报告相关测试结果、未接管 diff 和恢复条件；不自动换仓库写卡片。
```

四类最小改计划例子：

```text
范围缩小：
- 失败输出：全量测试失败，且堆栈落在启动前 dirty 的模块。
- 改计划：本轮只验证并提交当前文档；代码测试失败作为未接管边界交接，不扩大到全量修复。

顺序变更：
- 失败输出：diff --check 报 trailing whitespace。
- 改计划：先修格式并重跑 diff --check，再继续结构断言；不能直接跳到提交。

目标切换：
- 失败输出：候选 repo 启动前已有 staged/unknown 文件。
- 改计划：保留未知 staged 内容，只推进原任务中可独立验证的部分；跨项目切换仅限原任务已授权的选题范围。

交接改写：
- 失败输出：验证命令缺少依赖，当前环境无法安装。
- 改计划：最终报告把验证标为未完成，交接写下一轮第一条命令和所需依赖，而不是写“待验证”。
```

另一个例子：

```text
原计划：
- 提交新增卡片。

验证输出：
- 计数脚本显示 README 仍写 87 张，但实际已有 88 张。

计划调整：
- Order：先同步三个索引计数，再提交。
- Evidence：重新运行计数脚本，确认总数和 AI Agent 数量一致。
```

**反例 / 修正做法**：

```text
反例：
- `pnpm test` 失败，但失败看起来像旧问题；本轮仍按原计划继续改 UI，最后报告“主要功能已完成，测试待后续修复”。

修正：
- 先用 `git status --short` 和最小复现命令判断失败是否与本轮文件有关。
- 若失败来自本轮改动：暂停扩写范围，优先修复测试或回滚本轮可疑改动。
- 若失败来自既有脏改动：把计划改为“只提交文档/只提交当前文件”，最终报告写明 `pnpm test` 未能证明本轮目标，并在后续接力中给出下一条验证命令。
```

**坑**：

- 把失败输出当成“背景噪音”，notebook 里照旧写原计划，最终响应里只报好消息。
- 遇到 dirty worktree 仍然 `git add .`，用一个 commit 掩盖边界问题。
- 测试失败后只改最终措辞，不改变验证策略或实现方案。
- 搜索/读取没有结果时继续凭记忆写结论，没有切换查询方式或显式标注信息缺口。
- 把“失败后重试”当成唯一反应；有些失败应该导致切换目标、缩小范围或停止交接。

**交接写法**：

失败吸收后，notebook 的 `后续接力` 应直接体现变化，而不是复制原计划。可用以下模板：

```text
后续接力：下一次优先从 `relative/path` 继续；先 <第一条动作>；
本轮因 <失败输出摘要> 将 <范围/顺序/目标/交接> 从 <原计划> 调整为 <实际选择>；
验证用 <命令或检查>；若 <边界条件>，则改选 <备选路径>。
```

要点：

- 写出失败摘要（一句话即可），让下一轮不必重新排查。
- 写清调整方向（范围缩小 / 顺序变更 / 目标切换 / 交接延后），不要只写"已处理"。
- 若失败导致本轮无 target repo commit，交接中显式说明原因和下一步验证入口。

**检查**：每条关键失败输出都能在计划、执行记录或后续交接中看到对应变化；如果看不到范围、顺序、目标或交接的改变，就说明 Agent 只是观察到了失败，还没有吸收失败。
