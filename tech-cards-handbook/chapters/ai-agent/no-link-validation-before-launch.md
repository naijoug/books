# 无真实链接时先验证需求，不要伪造发布入口

## 问题

Agent 或独立开发者准备发布一个小产品、资料包、课程、服务 offer 时，经常会先把落地页、短帖、早鸟价、样刊和复盘模板都写好，但还没有真实的支付链接、留资表单、试读页、客服路径或渠道授权。

这时最容易出现两个坏选择：

1. 继续生产更多文档、更多 Day N 计划、更多样稿，把“准备发布”拖成内容囤积；
2. 把占位符当成真实入口，写出“已上线”“可购买”“已有反馈”的乐观总结，甚至伪造点击、私信或付费信号。

正确做法是把状态明确标成 `no-link validation mode`：不假装已经可交易，但也不停止验证。用一个低风险、人工可接住的动作去收集真实问题、真实原话和真实意向。

## 要点

- **先判断缺的是入口还是需求**：如果只缺支付 / 表单 / 样刊链接，但已经有渠道和人工回复能力，可以做无链接验证；如果连渠道授权和回复路径都没有，就只能准备执行包，不能代发。
- **CTA 从“购买”降级为“评论 / 私信领取样刊”**：无真实链接时，不提前收款，不承诺自动交付，不把占位链接伪装成链接。
- **只跑一个渠道、一个窗口、一个问题**：例如 30 分钟内在一个已授权渠道发布一条问题征集，观察评论、私信、样刊索取和早鸟意向。
- **记录用户原话而不是自我解释**：把原话、岗位、问题类型、是否愿意留资、是否问价格分开记录；不要把“点赞”直接推断为付费意向。
- **用 Continue / Narrow / Stop 决策**：有明确原话和下一步请求才继续；只有泛泛互动就缩窄定位；没有问题和私信就暂停内容生产。
- **把占位符变成替换清单**：在 repo 里保留 readiness check 或手工清单，列出哪些文件仍有 `[试读链接]`、`[留资链接]`、`[支付链接]`，拿到真实入口后逐文件替换。

## 示例

场景：准备发布一份“AI 技术面试题解”资料包，已有 Day 4 短帖、Day 5 问题征集、Day 6 早鸟转化和 Day 7 复盘模板，但真实试读链接和留资链接还没准备好。

不要这样写：

```text
资料包已经上线，点击 [试读链接] 购买。今天收到了很多正反馈。
```

这句话有三个问题：占位链接不是入口，“上线”状态不真实，“很多正反馈”没有证据形状。

可以降级成：

```text
我在整理一份 AI 技术面试题解样刊，先不放购买链接。
如果你最近在准备面试，评论 / 私信我一个最卡的问题：
- Agent 项目怎么写进简历？
- AI 可观测性 / 安全怎么答？
- 架构设计题怎么从 demo 讲到生产？

我会挑 3 个真实问题写进样刊，并把样刊发给提问的人。
```

同步记录一张表：

| 时间 | 渠道 | 用户原话 | 岗位 / 阶段 | 问题类型 | 是否索取样刊 | 是否询问价格 | 下一步 |
|---|---|---|---|---|---|---|---|
| 10:20 | 即刻 | “Agent 项目到底算业务项目吗？” | 后端 / 换工作 | 简历表达 | 是 | 否 | 回样刊 + 追问项目背景 |
| 10:37 | 社群 | “有没有可观测性那块的题？” | 算法转工程 | 可观测性 | 是 | 是 | 标记早鸟意向 |

30 分钟后再决策：

- Continue：至少 3 条具体问题 + 1 个样刊索取 / 早鸟意向；
- Narrow：只有某一类问题集中出现，例如都问“简历里的 AI 项目怎么写”；
- Stop：只有点赞、围观或泛泛鼓励，没有可复用原话。

## 坑

- **把占位链接当真实链接**：`[试读链接]`、`[留资链接]` 只能提醒后续替换，不能出现在对外发布稿里。
- **把“能写文案”误认为“能发布”**：Agent 可以准备草稿、检查清单和记录表，但没有 Offer / 实验、渠道和账号、联系路径、目标对象或受众、观察窗口五项授权时不能代发。
- **继续写 Day 8 / Day 9**：如果 Day 4–7 已经能支持验证，下一步应该执行或复盘，不是继续加计划。
- **提前收款但无法交付**：没有支付入口、交付路径和退款规则时，只收集意向，不收钱。
- **只看互动量**：点赞、收藏、转发只能当弱信号；真实问题、私信、样刊索取、价格追问才更接近需求证据。
- **伪造发布反馈**：没有实际外发就写“用户反馈很好”，会污染后续产品判断。

## 检查

在无真实链接的首发任务里，提交前问自己：

- 是否明确写出当前是 `no-link validation mode`，而不是“已上线”？
- 是否把 CTA 降级为评论 / 私信 / 样刊索取，而不是购买？
- 是否有一个授权渠道、人工回复路径和观察窗口？如果没有，是否只准备执行包、不宣称已发布？
- 是否记录用户原话、问题类型、样刊索取、早鸟意向，而不是只记曝光量？
- 是否有 Continue / Narrow / Stop 判读规则？
- repo 中是否还有占位链接清单，方便拿到真实入口后逐文件替换？
- 最终报告是否写清“没有外发 / 没有真实链接 / 没有伪造反馈”的边界？
