# 工作日志是可复用资产，不要写成心情流水账

**问题**：周期性唤醒的 Agent 每轮都会写 notebook、summary 或 handoff；怎样让这些记录真正帮助下一轮选择工作、验证边界和积累可复用经验，而不是变成“我做了什么”的流水账？

**要点**：

- 日志首先服务接力决策：必须写清当前状态、候选工作、取舍理由、实际推进、验证证据和下一条动作。
- 记录要区分事实、推断和计划：事实来自命令输出或文件内容，推断要标明依据，计划要能被下一轮直接执行或否决。
- 每轮至少沉淀一个可复用信号：失败模式、验证命令、边界判断、可复制模板、产品化线索或被排除的风险。
- 不要把日志当成本轮成果本身；如果存在低风险小任务，先推进实际资产，再用日志解释为什么这样推进。
- 日志里的路径、命令和 commit 证据要可复核；避免写本机绝对路径、模糊描述或无法重放的“已处理”。

**示例**：

```text
低价值流水账：
- 今天看了项目，觉得应该继续写书。
- 更新了 summary。
- 下次继续优化。

可复用工作日志：
- 当前状态：books clean；summaries 有启动前未接管 openclaw 记录；loom 有大量既有 dirty path。
- 候选工作：补一张 AI Agent 卡片、接管 loom UI、写 docs 教程。
- 本轮选择：补卡片，因为 books clean、改动小、可用统一 verifier 证明索引和链接未破。
- 验证证据：python3 scripts/verify_tech_cards.py --full-only 通过，统计 216 cards。
- 后续接力：下一轮若继续书稿，优先检查这张卡是否需要进入样本包。
```

把日志当成资产时，下一轮 Agent 不需要重新猜“为什么没碰 loom”或“哪个命令能证明书稿索引没坏”，而是可以直接复用边界和命令。

**坑**：

- 只写完成项，不写启动前 dirty 状态，导致下一轮误以为所有未提交文件都是可接管范围。
- 只写计划，不写为什么放弃其他候选工作，下一轮无法判断取舍是否仍成立。
- 把验证写成“检查通过”，但不写命令、输出摘要或人工复核标准。
- 每轮都写新的总结文档，却没有推进任何可提交资产，也没有解释为什么当轮只能观察。
- 在日志中使用本机绝对路径，让记录无法直接复制到另一台机器或另一个 agent。

**检查**：读完一条工作日志后，下一轮应该能回答四个问题：我能安全接管哪些文件、哪些文件必须避开、下一条低风险命令是什么、上一轮验证到底证明了什么。如果回答不了，就把日志改成“事实 -> 取舍 -> 证据 -> 下一动作”的格式，而不是继续补感想。
