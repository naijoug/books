# 无人值守 Agent 要选择默认动作，不要等待澄清

**问题**：cron、scheduled job 或 CI 里的 Agent 没有用户在场，遇到轻微歧义时应该怎么办？

**要点**：

- 先判断歧义是否真的会改变下一条工具调用；不会改变时，采用最安全、最小范围的默认解释继续推进。
- 默认动作要同时满足三点：低风险、可验证、可回滚；例如只读检查、path-limited 文档改动、聚焦测试。
- 如果歧义涉及外部副作用、账号权限、删除数据或跨 repo 大改，停止在只读阶段，并把需要用户决策的问题写成下一段接力。
- 最终记录要写出本轮采用的默认解释，而不是假装用户已经确认。

**示例**：

```text
输入：检查“当前项目”还有什么值得推进。
环境：workspace 根目录不是 git repo，多个子 repo dirty，用户不在线。
默认解释：先检查各子 repo 状态；不接管启动前 dirty path；选择 clean repo 中一个独立、可验证的小文档任务。
验证：只对本轮文件跑 git diff --check 和结构断言；提交后读回 hash。
交接：说明哪些 dirty path 未接管，下一轮第一步先重新跑启动快照。
```

**反例 / 修正做法**：

```text
反例：
“要不要继续 loom？”不确定，于是停止，最终只写“等待用户确认”。

修正：
先读当前状态。若 loom 启动前已有 staged/dirty path 且归属不明，就明确不接管 loom；
改选 clean repo 的小任务，并在 notebook 写清“默认采用不接管未知 dirty path”的解释。
```

**坑**：

- 把“不能问问题”理解成可以猜测用户授权，直接提交来源不明的改动。
- 为了避免犯错而完全不行动，只留下空泛计划；这会让心跳任务退化成噪音。
- 采用默认解释后不记录，下一轮无法判断这是主动取舍还是遗漏。

**检查**：无人值守记录里能否看到“默认解释是什么、为什么低风险、验证证据在哪里、哪些问题留给用户决策”？如果只有“因无人确认未执行”，说明 Agent 还没有学会在短节拍里自治。
