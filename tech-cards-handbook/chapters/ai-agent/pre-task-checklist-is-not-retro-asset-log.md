# Pre-task checklist is not retro asset log

## 问题

在附录、SOP 或 Agent 任务模板里，`使用前检查清单` 和 `复盘/体检记录卡` 经常共享目标、权限、人工确认、验证证据、失败回退等字段。看到复盘模板里有 `可复用沉淀`，很容易顺手把同一字段塞进使用前清单；但如果这张清单的职责是任务开始前的风险闸门，强行加入结束后的资产字段，会让读者在启动阶段就背上复盘表的复杂度，也会让 Agent 误以为自己已经接管了整组附录模板。

## 要点

- **先写模板职责，而不是先补字段。** 使用前清单回答“现在能不能开始、能看什么、能改什么、如何验收、出错如何停”；复盘记录卡回答“这次实际发生了什么、留下了什么资产、下次怎么改”。
- **共享字段只同步到同一生命周期。** 权限、人工确认、验证证据和失败回退属于任务前就要声明的边界；`可复用沉淀` 通常属于任务后复盘，除非该清单明确用于规划“本轮必须产出可复用资产”。
- **给 A.1 这类前置入口补一句定位说明，往往比加一行字段更安全。** 例如写清“本清单只决定是否启动任务，任务后的资产沉淀由 A.14 / A.15 承接”。
- **不要在大 dirty diff 里用字段统一掩盖 ownership。** 如果同一文件还混有章节改写、README 审校记录或表格重排，本轮只能留下字段职责判断，不能提交整份文件。
- **验证要检查职责边界。** 附录类改动除了链接校验，还应断言前置清单没有误收复盘字段，或明确包含“由复盘模板承接”的说明。

## 示例

处理 `使用前检查清单` 与 `工作流体检记录卡` 的字段差异时，先写一张职责分界表：

| 字段 | 使用前检查清单 | 复盘 / 体检记录卡 | 决策 |
|---|---|---|---|
| 任务目标 / 输入材料 | 必须有 | 可记录真实输入 | 同步；启动前就要明确。 |
| 权限边界 | 必须有 | 复盘实际权限是否过大 | 同步；前置声明，事后校正。 |
| 人工确认点 | 必须有 | 记录采纳 / 拒绝理由 | 同步；启动前列红线，事后留证据。 |
| 验证证据 | 必须有验收口径 | 记录实际证据位置 | 同步；前置定义，事后填证据。 |
| 失败回退 | 必须有停止方式 | 记录异常和回滚 | 同步；前置闸门。 |
| 可复用沉淀 | 仅当任务目标要求资产化时才出现 | 必须记录实际沉淀 | 默认不强行同步；用定位说明交给复盘模板承接。 |

可以把 Go / Narrow / Stop 写成下一轮可执行判断：

```text
Pre-task vs retro decision
- Go: A.1 的标题、说明或使用场景已经要求“本轮必须留下模板/脚本/案例”，则补 `可复用沉淀`，并只提交附录字段对齐。
- Narrow: A.1 只是任务前风险闸门，则补一句职责说明，说明沉淀出口由 A.14 / A.15 承接。
- Stop: A.1 所在文件同时有大规模章节改写、格式 churn 或未知归属 dirty，先不要改文件，只在 notebook/tech-card 留决策。
```

最小内容断言示例：

```bash
python3 - <<'PY'
from pathlib import Path
text = Path('ai-personal-growth/chapters/appendix.md').read_text()
assert 'AI 使用前检查清单' in text
assert '工作流体检记录卡' in text
assert '可复用沉淀' in text
assert '任务前' in text or '使用前' in text
print('pre-task vs retro boundary checks passed')
PY
```

这条断言不是要求所有字段统一，而是防止“任务前清单”和“任务后沉淀”被混成一张不可执行的大表。

## 反例 / 修正

反例：

```text
A.14 有“本周沉淀资产” -> A.1 没有 -> 直接在 A.1 加“可复用沉淀” -> git add appendix.md
```

问题是 A.1 可能只是启动闸门，用户在任务开始前未必知道最终会沉淀什么；如果同一 `appendix.md` 还是启动前 dirty，这个提交还会混入未知改动。

修正：

```text
先判断模板生命周期 -> 如果是前置闸门，只补职责说明或只写接力决策 -> 如果确实要求资产化，再单独接管字段对齐 -> 用内容断言和 diff check 验证
```

## 坑

- 为了“字段整齐”，把任务前清单、Agent 委派卡、周复盘表都改成同一张大表。
- 把 `可复用沉淀` 写成启动前必填项，却没有说明可以填“本轮不要求资产化”。
- 只看某个 hunk 是否缺字段，不看同一附录里是否已有复盘模板承接该字段。
- 在未知 dirty 文件中补一行小字段，然后提交整份文件。
- 验证只跑全书链接，不检查模板职责说明是否仍存在。

## 检查

- 是否先说明这张模板属于任务前、任务中还是任务后？
- 字段差异是生命周期差异，还是确实遗漏？
- 如果不补 `可复用沉淀`，是否写清由哪张模板承接？
- 如果要补字段，是否只接管附录字段对齐，不混入章节正文或格式 churn？
- 是否用内容断言、链接校验和 `git diff --check` 验证本轮改动？
