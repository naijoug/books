# 试点报价卡把兴趣变成交易，不要把“愿意试试”当付费信号

**问题**：AI 编程审查、OpenClaw 配置服务或小自动化脚本服务已经有人说“挺有意思”“可以看看”时，为什么还不能直接判断需求成立？下一步应该怎样把模糊兴趣压成可验证交易？

**要点**：

- 区分 `interest`、`commitment` 和 `transaction`：点赞、口头鼓励和“有空看看”只是兴趣；愿意给真实材料、安排时间、承担试点费用或明确下一步代价，才是承诺；试点有价格、交付、验收和结束决策，才接近交易证据。
- 试点报价卡不是长期套餐：它只验证一个最小切口是否值得继续，周期、输入、输出、边界和价格都要小到对方能低风险决定。
- 报价前先写交付边界：不接生产权限、不保证全量修复、不替代安全审计、不把一次报告包装成长期顾问。
- 客户投入要显性化：哪怕不收费，也必须要求脱敏样本、30 分钟复盘、允许记录匿名痛点、或给出继续 / 缩小 / 停止判断；没有任何代价的“试试”只能算弱兴趣。
- 试点结束必须有 `Continue / Narrow / Stop`：继续才讨论套餐、模板或工具化；缩小就调整目标用户或输入要求；停止就记录拒绝原因，不继续堆产品表面。

**示例**：

```text
试点报价卡

目标对象：小团队最近一次 AI agent 代码改动已经合并，但担心测试覆盖和交接不稳。
周期：2 个工作日内完成异步审查 + 30 分钟复盘。
客户输入：
- 1 个仓库或 PR 链接；
- 最近一次 agent final report / handoff；
- 当前 CI 或本地验证命令；
- 可公开范围：Private / Anonymous / Public。

交付结果：
- 1 页 AI Coding Audit Report；
- Top 5 风险；
- 下一条安全命令梯；
- 未验证项和下一轮 handoff 模板。

试点价格：¥X 或等价承诺（真实脱敏样本 + 复盘时间 + 是否继续的明确反馈）。
边界：只读审查，不接密钥，不改生产代码，不承诺修完所有问题。
验收：复盘后客户能说清下一轮 agent 先做什么、哪些 path 不能碰、哪些验证必须补。
结束决策：Continue / Narrow / Stop，并记录原因。
```

这张卡的目的不是“卖贵”，而是尽早发现对方是否愿意为风险收敛付出真实代价。如果对方只愿意泛泛聊天，不愿意给材料、时间、预算或反馈承诺，本轮只能记录为兴趣信号，不能升级成需求成立。

**反例 / 修正做法**：

```text
反例：
- 对方说“这个 AI 审查方向不错”。
- Agent 继续写 landing page、FAQ、三档价格和自动化脚本。
- 一周后仍没有真实 repo、预算、复盘时间或拒绝原因。

修正：
- 只发一张试点报价卡。
- 要求对方在 48 小时内二选一：提供材料进入试点，或说明暂时不做的原因。
- 没有回复就 Stop / Park，不继续扩同一 offer 表面。
```

**坑**：

- 把“愿意了解”当“愿意付费”，导致后续全是自嗨式产品化。
- 把试点做成完整咨询项目，输入太多、价格太高、周期太长，早期客户无法决策。
- 为了降低阻力把价格删掉，结果试点没有任何代价，也无法判断真实需求。
- 没有写排除边界，试点过程中被拉进生产修复、工具选型、培训和长期值守。
- 试点结束只写“客户觉得不错”，没有 `Continue / Narrow / Stop` 和下一条证据动作。

**检查**：准备把兴趣信号升级为收入实验时，先确认：是否写清目标对象、周期、输入、输出、边界、价格或等价承诺、验收方式和结束决策；客户是否需要付出钱、材料、时间或明确反馈；试点是否能在不接生产权限的情况下交付；最终记录是否区分兴趣、承诺和交易证据；若对方无回应，是否停止扩同一 offer 表面。
