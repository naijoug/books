# 规划要选择工作，不要只复述状态

**问题**：周期性运行的 Agent 很容易把“复盘”和“总结”当成成果，如何让规划真正推动下一步行动？

**要点**：

- 规划必须产生取舍：候选项、选择项、放弃项和选择理由都要写清。
- 选择要落到一个低风险、可验证的小块，而不是停在宏观方向。
- 如果本轮只能观察，也要把观察结果转成下一轮的第一条可执行动作。
- 规划记录不是给本轮看的，而是给下一轮接力判断“该不该继续这条线”看的。

**示例**：

```text
候选工作：
- A：补一张 AI Agent 卡片，范围小，可通过文件存在和索引计数验证。
- B：重构 Loom 工作流页面，价值高，但当前已有未提交改动，容易混入他人变更。
- C：整理 docs AI 文章，已有未提交文件，先不覆盖。

本轮选择：A。
选择理由：仓库干净、变更小、能形成可复用资产，并且不会碰已有未提交工作。
下一步动作：新增卡片 -> 更新 ai-agent/README 和书籍 README 计数 -> 检查 git diff -> 提交。
```

**坑**：把规划写成“继续推进 AI 能力建设”“后续完善项目”这类愿望句。它看似完整，却没有排除项、没有风险判断、没有第一条命令，下一轮仍然要重新猜。

**反例 / 修正做法**：

反例：Agent 在 notebook 里写“当前状态良好，本轮继续写作，下一段继续优化内容”，然后没有说明为什么不是做项目、为什么不是修已有文档、也没有实际修改文件。下一次心跳只能读到一段积极描述，无法判断哪个资产值得继续投入。

修正版：先查看相关仓库状态，避免碰到已有用户改动；再列出 2–3 个候选任务，用“价值 / 风险 / 可验证性 / 本轮大小”筛选；最后只执行一个小块。即使没有执行，也要留下下一轮可直接运行的检查命令或目标文件路径。

**检查**：读完规划后，另一个 Agent 能否在 1 分钟内判断“本轮为什么做这件事、哪些事故意没做、下一步从哪里开始”？能，才算有效规划。
