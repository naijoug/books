# Agent 是模型、工具、循环和边界的组合

**问题**：怎么判断一个程序是不是 Agent，而不只是一次普通模型调用？

**要点**：

- Agent 至少包含模型、工具、决策循环和停止条件。
- 模型负责判断下一步，工具负责改变或查询外部世界。
- 停止条件和权限边界决定它是否可控。

**示例**：

```text
用户目标 -> 模型判断 -> 选择工具 -> 读取结果 -> 再判断 -> 输出或停止
```

**坑**：只接上工具但没有迭代上限、错误处理和权限边界，Agent 很容易从“自动化”变成“失控重试”。

**反例 / 修正做法**：

- 反例：把客服机器人描述成“接入 `SearchTickets`、`RefundOrder` 和 `SendEmail`，让模型自己判断直到解决问题”。这只列出了工具，没有说明循环如何读取结果、最多尝试几次、退款权限边界是什么，也没有说明连续失败时何时交还人工。
- 修正版：写成“模型每轮只能在 `SearchTickets`、`DraftReply`、`EscalateToHuman` 中选一个工具；`RefundOrder` 只允许在人工审批事件存在时由后端策略触发；同一工单最多 3 轮自动处理；任一工具返回 `permission_denied`、连续 2 次 `timeout` 或用户明确表达投诉升级时，必须停止并调用 `EscalateToHuman`，报告已读 ticket、最后一次工具结果和未完成目标”。

**检查**：为每个 Agent 写清楚五件事：模型要判断什么？工具能查询或改变什么？循环如何读取结果继续？最多运行多久？权限或失败条件触发时什么时候必须停下来交还控制权？
