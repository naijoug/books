# AI 助手操作系统先分清身份、用户、工具和心跳

**问题**：如何把一堆 prompt、偏好、工具说明和运行记录整理成可维护的助手系统？

**要点**：

- 身份层约束助手如何工作。
- 用户层记录正在帮助谁。
- 工具层记录当前环境可用能力。
- 心跳层记录长期任务如何防止漂移。

**示例**：

```text
assistant-os/
├── SOUL.md       # 行为原则
├── USER.md       # 用户偏好
├── TOOLS.md      # 环境约定
├── HEARTBEAT.md  # 周期自检
└── memory/       # 带来源和日期的记录
```

**坑**：把所有内容塞进一个超长系统提示，会让更新、审计和脱敏都变困难。

**反例 / 修正做法**：

反例：为了“让助手更懂我”，把身份原则、用户住址和账号偏好、所有工具 schema、最近 30 次 cron 运行记录、临时写作任务以及 API key 备注都追加到同一个 `SYSTEM_PROMPT.md`。结果是每次改工具说明都要重审整份提示，交给另一个 Agent 时无法只隐藏敏感用户信息，也无法判断某条运行记录是否已经过期。

修正版：先按层拆分来源与生命周期：`SOUL.md` 只放长期行为原则；`USER.md` 只放用户偏好且标注敏感级别；`TOOLS.md` 只放当前环境可用工具、输入边界和禁止事项；`HEARTBEAT.md` 只放周期任务的计划—执行—验证—写回规则；`memory/` 中的运行记录必须带日期、来源和失效条件。组装上下文时只加载本轮需要的层，临时任务完成后写入 notebook 或归档，不再回灌进身份层。

**检查**：任意一条信息是否能归入“我是谁、我帮谁、我能用什么、我如何持续运行”之一？不能归类时，先不要写进核心层。
