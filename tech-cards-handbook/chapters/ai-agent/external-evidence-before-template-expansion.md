# 真实样例先于模板扩张，不要在无外部证据时继续堆产品表面

**问题**：Agent 在收入实验或小服务 offer 里已经写出 starter、README、测试和交付清单后，为什么不能因为 repo 仍然 clean、还能继续写，就一轮轮新增同类模板、落地页和销售文案？

**要点**：

- 先区分 `internal readiness` 和 `external evidence`：本地脚本、fixture、测试和说明只能证明“能交付一个样例”，不能证明“有人需要这个服务”。
- 当已有资产足够支撑一次真实诊断时，下一步默认不是扩模板，而是请求 1 份脱敏输入、期望输出和人工确认点。
- 继续写产品表面前必须有新证据：真实用户原话、脱敏样例、失败输入、价格追问、预约诊断、已授权渠道或明确拒绝原因。
- 没有外部证据时，可以做一次健康检查、漂移扫描或风险边界修正；检查通过后应停止同方向生产，切换到能产生新证据的资产。
- notebook 的后续接力要写成“下一条取证动作”，而不是“继续优化 README / 再补一个模板 / 做完整站点”。

**示例**：

```text
当前状态：
- `makemoney/` 已有小型自动化脚本服务说明。
- 已有两个 CSV starter：状态汇总、订单异常标注。
- 每个 starter 都有脱敏样例、期望报告和测试。

候选工作：
1. 再补第三个模拟模板。
2. 写完整落地页和购买按钮。
3. 用 intake 表向 1-3 个真实线索收集脱敏 CSV、期望输出和人工确认点。

证据判断：
- internal readiness：通过，本地能演示。
- external evidence：不足，没有真实样例、预约、渠道授权或价格追问。

决策：
- Stop template expansion。
- 下一步只做取证：发送 intake 表、记录用户原话、等待真实样例；若无人响应，切换到其他收入实验或内容资产。
```

**反例 / 修正做法**：

```text
反例：
第 1 轮写 CSV 汇总模板；第 2 轮写订单异常模板；第 3 轮写库存模板；第 4 轮写客服模板；
每轮都有测试和 README，但没有任何真实用户提供脱敏输入。

修正：
第 2 个模板跑通后，设置停止条件：
- 若没有 1 份真实脱敏输入，不再新增模拟模板；
- 若没有真实发布渠道，不写“已上线 / 可购买”；
- 若没有反馈，只允许做健康检查和风险词漂移扫描；
- 下一轮优先执行 `docs/small-automation-script-intake.md` 的取证动作。
```

**坑**：

- 把“还有很多场景可以自动化”误当成需求证据；场景想象不是用户痛点。
- 用测试通过制造进展感；测试只能证明样例可复跑，不能证明有人愿意付费。
- 在没有真实链接、真实渠道或人工回复路径时写“已上线”“可购买”“客户反馈很好”。
- 因为外部取证需要等待，就回到 repo 里继续打磨同一批模板，导致收入实验变成内容囤积。
- 后续接力只写“继续完善产品线”，没有指定下一条真实取证动作和停止条件。

**检查**：准备继续扩一个收入实验前，先回答五句：现有资产是否已经能支撑一次真实诊断？新增表面依赖哪条外部证据？如果没有证据，本轮是否只做健康检查或风险修正？下一步取证动作是否指向真实人、真实渠道或真实脱敏样例？最终报告是否明确写清没有伪造链接、付费、反馈或发布状态？
