# 启动层只负责初始化，不应该长期参与运行

**问题**：`BOOTSTRAP`、初始化脚本或新手引导应该保留在长期运行上下文里吗？

**要点**：

- 启动层适合第一次询问身份、补齐配置、创建目录。
- 初始化完成后，运行时应读取稳定文件，而不是反复执行启动逻辑。
- 如果保留历史模板，要标注它是素材，不是当前状态。

**示例**：

```text
第一次运行：BOOTSTRAP.md -> 生成 IDENTITY.md 和 USER.md
后续运行：读取 IDENTITY.md、USER.md、TOOLS.md、HEARTBEAT.md
```

**坑**：长期保留未标注的启动模板，会让后续维护者分不清“待初始化”和“已初始化”。

**反例 / 修正做法**：

反例：仓库第一次创建时写了 `BOOTSTRAP.md`，里面说“接下来先建立 `docs/`、`books/`、`skills/` 三个目录”。半年后这些目录早已存在，但 cron 仍把这段启动说明当成当前任务，每次都计划“初始化知识库结构”，并忽略 `summaries/hermes/YYYY-MM-DD.md`、`git status --short` 和实际项目文件。

修正版：初始化脚本完成后，把长期身份、偏好和工具约束迁移到稳定文件，例如 `IDENTITY.md`、`USER.md`、`TOOLS.md` 或每日 notebook；把 `BOOTSTRAP.md` 标注为“历史初始化素材”。后续运行必须先读当前 notebook 与 repo 状态，再决定是否要创建目录、补索引或修改正文。若 `BOOTSTRAP.md` 和当前状态冲突，以当前文件系统与 git 状态为准，并在交接中说明“启动模板已过期，不作为本轮事实来源”。

**检查**：删除启动模板后，助手是否仍能正常说明身份、读取偏好并执行任务？如果能，启动层已经完成使命。
