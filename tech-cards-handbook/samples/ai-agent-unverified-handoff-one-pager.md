# AI Agent 未验证项显式交接一页纸

用于短节拍 Agent 已完成一部分工作、但仍有边界没有验证的收尾阶段。目标不是把未验证项写成一句“待后续确认”，而是把**已验证事实、未验证边界、结论措辞、下一步第一条动作**拆开，让下一轮能直接接力。

## 1. 先写未验证项台账

```text
本轮目标：<本轮承诺交付的最小范围>
已验证事实：<命令 / 结构断言 / 构建 / 人工可复核标准>
未验证边界：<具体没覆盖的路径、交互、平台、数据、外部服务或性能边界>
未验证原因：<时间盒 / 环境限制 / 权限缺失 / 启动前 dirty path / 非本轮范围>
结论降级：本轮只能说 <可信结论>，不能说 <更强但未验证的结论>
下一步第一条动作：<下一轮可复制的第一条命令、文件读取或人工检查>
```

## 2. 四格收尾模板

```text
| 项 | 写法 |
|---|---|
| 已验证 | <列命令和结果摘要；不要只写“验证通过”> |
| 未验证 | <写具体边界和原因；不要写“部分未测”> |
| 结论措辞 | <把最终报告中允许说的话和不能说的话分开> |
| 下一步 | <第一条动作 + 若失败/仍缺权限时的处理规则> |
```

## 3. 常见场景

### A. 只跑了静态检查，没有跑完整构建

```text
已验证：`python3 scripts/check-markdown-proof.py documents/trending/ai/example.md` 通过；`git diff --check -- documents/trending/ai/example.md` 通过。
未验证：没有运行 VuePress 全量构建；原因是本轮只修改单篇 Markdown，且重型构建留给集成边界。
结论措辞：本轮只能说“单篇 Markdown 的 frontmatter、相对链接和空白检查通过”，不能说“站点构建已通过”。
下一步：如需发布前确认，先在 `docs/web/vuepress` 运行 `npx -y pnpm@8.15.9 run docs:build`；若构建失败，按构建日志定位插件、sidebar 或 include 问题。
```

### B. 代码测试覆盖了逻辑层，没有覆盖真实 UI

```text
已验证：`npm test -- reducer.test.cjs` 通过，覆盖状态迁移和 selector 输出。
未验证：没有在真实桌面应用中点击任务详情、设置页和日志过滤；原因是本轮未启动 GUI。
结论措辞：本轮只能说“状态逻辑已验证”，不能说“端到端交互体验已验证”。
下一步：启动应用后按 `打开任务 -> 切换日志过滤 -> 查看详情 pane` 的手工路径检查；若 UI 行为不一致，先记录截图或 DOM 观察，再改实现。
```

### C. 外部服务或账号权限不可用

```text
已验证：本地 dry-run、payload schema 和 mock fixture 均通过。
未验证：没有调用真实外部 API；原因是 cron 环境没有账号授权或凭据。
结论措辞：本轮只能说“本地请求构造和 dry-run 通过”，不能说“真实集成已可用”。
下一步：拿到授权后先运行只读健康检查；若仍无凭据，保持 mock 验证，不要代替用户创建外部副作用。
```

## 4. 最终报告句式

```text
验证证据：<命令 1 -> 结果摘要；命令 2 -> 结果摘要>。
未验证项：<具体边界>；原因是 <限制或归属>。
结论边界：本轮已证明 <可信事实>；尚未证明 <未覆盖结论>。
下一段接力：先 <第一条动作>；如果 <失败条件>，则 <缩小/修复/停止/继续交接规则>。
```

## 5. 收尾检查

- “未验证”是否具体到路径、命令、交互、平台或外部服务，而不是笼统写“待验证”？
- 最终报告是否把已验证事实和未验证推断分开？
- 下一步是否是一条可执行动作，而不是“继续完善”？
- 如果未验证项来自启动前 dirty path 或权限缺失，是否明确不接管、不编造验证结果？
- notebook 或交接记录是否能让下一轮直接复制第一条动作？
