# AI Agent Workflow Cards Day 1 发送记录

> 用途：配合 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-day1-send-queue.md` 使用。这个文件只记录真实发送状态，不填写虚构联系人、不伪造反馈；如果暂时没有真实对象，就保持空表，等待人工回填。

## 填写规则

1. 每一行对应一次真实前置询问；没有发送就不要新增“已发送”。
2. 联系人用用户自己能识别的代号即可，不写隐私信息；例如 `熟人-A`、`团队规范-B`、`社群案例-C`。
3. 样品包只有在对方愿意试读后才发出；若直接发了，也要在“是否先问再发”里标记为“否”。
4. 回复必须按原意归类，不为了验证成功而美化；“没时间”“不使用 agent”也是有效拒绝原因。
5. 收到具体反馈后，再同步回填到 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-feedback-tracker.md`；本表只做 Day 1 执行流水。

## 状态枚举

| 状态 | 含义 | 下一步 |
|---|---|---|
| 待发送 | 已选定对象，但还没有发消息 | 发送前检查是否符合 Day 1 条件 |
| 待回复 | 已发前置询问，尚无回复 | 等待；24 小时后最多轻提醒一次 |
| 愿意试读 | 对方同意看 Markdown，但样品包未发 | 发送 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-sample-pack-v0.1.md` |
| 已发样品包 | 已发送样品包，等待具体反馈 | 约定反馈时间，并准备回填反馈跟踪表 |
| 拒绝 | 对方明确不看 | 记录原因；不追问超过一次 |
| 延后 | 对方表示晚点看 | 记录可接受的跟进时间，不催促 |

## 24 小时后复盘

| Day 1 结果 | 判断 | 动作 |
|---|---|---|
| 3 人中至少 2 人愿意试读 | 开场白基本有效 | 发出样品包；Day 2 等待反馈，不改样品包正文 |
| 只有 1 人愿意试读 | 对象或场景可能不够窄 | Day 2 优先找更贴近 agent 失败场景的人 |
| 0 人愿意试读，原因集中在没时间 | 请求成本过高 | 缩短消息，只问一个最想解决的 agent 失败场景 |
| 0 人愿意试读，原因集中在不理解价值 | 定位表达不清 | 按 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-v0.2-revision-rules.md` 只改一句话定位 |
| 收到具体失败案例 | 出现有效信号 | 回填 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-feedback-tracker.md`，Day 4 再归类 |

## 不记录的内容

- 不记录真实姓名、手机号、邮箱等隐私信息；
- 不把“准备联系”写成“已联系”；
- 不把对方客套话归类为有效反馈；
- 不在本表里重写样品包；
- 不为了让指标好看而删除拒绝记录。
