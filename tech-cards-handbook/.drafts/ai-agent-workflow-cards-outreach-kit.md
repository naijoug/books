# AI Agent Workflow Cards 验证外联包

> 用途：配合 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-sample-pack-v0.1.md` 做 7 天验证。目标不是“宣传书稿”，而是在小范围真实开发者中验证：这个样品包是否解决了足够具体的 agent 工作流痛点，以及是否值得继续做成完整 25 张卡片的付费产品。

## 验证目标

### 目标读者

优先找这 3 类人：

1. **已经在写代码时使用 coding agent 的程序员**：用过 ChatGPT、Codex、Claude Code、Cursor、Devin、OpenClaw 或类似工具。
2. **正在把 agent 接入团队流程的人**：关心工具权限、日志、记忆、交接和失败恢复。
3. **有长任务失败经历的人**：遇到过 agent 越跑越偏、重复尝试、只口头总结、不留下可复查证据的问题。

暂时不找：完全没用过 AI 编程工具的人、只关心模型榜单的人、只想要 prompt 合集但不愿改工作流的人。

### 本轮要验证的 4 个问题

1. 读者是否能在 10 分钟内看懂 5 张样卡的价值？
2. 样卡是否能让读者马上改写一个自己的 agent 指令或工作流？
3. 读者是否还想要完整 25 张卡，以及更偏向 Markdown、PDF、Notion 还是网页形式？
4. 读者是否愿意留下邮箱、预约访谈，或为完整包支付一个小额早鸟价？

### 成功信号

| 信号 | Continue | Narrow | Stop / Rethink |
|---|---:|---:|---:|
| 目标读者回复率 | 10 人中 ≥ 4 人回复 | 10 人中 2-3 人回复 | 10 人中 ≤ 1 人回复 |
| 有效反馈 | ≥ 3 条具体使用场景 | 1-2 条具体场景 | 只有礼貌性反馈 |
| 转发/收藏/索取完整包 | ≥ 2 次 | 1 次 | 0 次 |
| 付费或早鸟意向 | ≥ 1 个明确意向 | 只愿意免费试用 | 明确认为不需要 |

## 一页 Landing Page 文案

### 标题

AI Agent Workflow Cards：把一次性 prompt 变成可运行、可复盘、可接力的工作流

### 副标题

25 张给程序员的 agent 工作流卡片。每张只解决一个具体失败模式：边界、工具、记忆、迭代上限、检查点、交接、验证和恢复。

### 适合谁

- 你已经在用 ChatGPT、Codex、Claude Code、Cursor、OpenClaw 或类似 coding agent。
- 你不缺 prompt，但经常发现 agent 跑久后偏离目标。
- 你希望 agent 的每次行动都有证据、可回滚、可复盘、可交接。
- 你想把个人使用经验沉淀成团队可复用的工作流规范。

### 你会得到什么

免费样品包先给 5 张卡：

1. Agent 不是模型，而是模型、工具、循环和边界。
2. 工具描述要写用途和输入，不要只写名字。
3. 给 Agent 设迭代上限和失败出口。
4. 记忆不要全塞进 prompt。
5. 长任务要用心跳工作流防漂移。

完整包计划包含 25 张卡，覆盖：工具调用、状态观察、权限边界、失败恢复、长期记忆、任务切块、验收标准、多人接力和团队落地。

### 立即可用的结果

读完样品包后，你可以拿其中的模板改写自己的下一条 agent 指令：

```text
目标：{goal}
允许工具：{tools}
禁止动作：{forbidden_actions}
最多运行：{max_iterations} 轮 / {max_minutes} 分钟
每完成 {checkpoint_interval} 汇报：已完成、证据、阻塞、下一步
连续失败 {failure_limit} 次后停止并交接
```

### 反馈请求

如果你愿意试读，我只想问 5 个问题；前 3 个用于判断卡片是否真的解决了工作流问题，后 2 个用于判断是否值得继续产品化：

1. 你最近一次让 coding agent 失败、跑偏或不可复盘的具体案例是什么？
2. 哪张卡最像这个真实问题，为什么？
3. 哪张卡最弱、最像废话，应该删掉或重写？
4. 如果有完整 25 张卡，你希望它是什么形式：Markdown、PDF、Notion 还是网页？
5. 你是否愿意留下邮箱/后续提醒、推荐给同事，或接受一个小额早鸟价？为什么？

记录时不要只写“喜欢/不喜欢”，要同步填入 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-feedback-tracker.md` 的反馈证据日志：可观察事实、推断、置信度、当前分级和下一步验证动作。

### CTA

回复「样品包」获取 Markdown 版本；或直接回复一个你最近遇到的 agent 失败案例，我会用卡片结构帮你改写成一个可执行工作流。若你看完愿意继续收到完整 25 张卡的早鸟版本，也可以顺手留一个邮箱或 preferred contact。

## 私信模板

### 模板 A：给熟悉的开发者朋友

```text
我在做一个小验证：AI Agent Workflow Cards，目标是把“让 agent 写代码”从一次性 prompt 变成可运行、可复盘、可交接的工作流。

先做了 5 张免费样卡，都是很具体的问题：工具描述怎么写、迭代上限怎么设、长任务怎么防漂移、memory 怎么分层。

你最近也在用 coding agent，所以想请你帮我看 10 分钟。只需要回答 5 个问题：最近一次具体失败案例、哪张最有用、哪张最弱、想要什么形式、是否愿意继续收到完整包/推荐给别人。

如果方便，我把 Markdown 发你；如果现在没时间，也可以直接回一个失败案例，我先帮你按卡片结构改成可执行工作流。
```

### 模板 B：给技术社群中的半熟人

```text
你好，我在验证一个面向程序员的 AI agent 工作流小产品：25 张 workflow cards。

它不是 prompt 合集，而是把 agent 常见失败模式拆成可检查的卡片，例如：
- 工具描述只写名字导致 agent 乱调用；
- 长任务没有心跳，跑着跑着偏离目标；
- memory 全塞进 prompt，越用越混乱；
- 工具调用没有可观察证据，只剩口头总结。

我现在有 5 张 Markdown 样卡，想找已经用过 coding agent 的开发者试读。你愿意看一版并给 3-5 分钟反馈吗？
```

### 模板 C：给公开内容作者或工具开发者

```text
我看到你经常分享 AI 编程 / agent 工具相关内容，想请教一个产品化方向。

我在做 AI Agent Workflow Cards：用短卡片总结程序员使用 agent 时的工作流边界和检查点。目标读者是已经会用工具、但想减少失控重试和不可复盘输出的人。

现在有 5 张免费样卡。你看完后只需要告诉我：这个方向是有传播价值，还是更像内部笔记；哪张卡最强/最弱；以及你认为目标读者是否会留下邮箱或早鸟意向。如果你愿意，我可以发 Markdown 版本。
```

### 模板 D：冷启动短版

```text
我在做一份给程序员的 AI Agent Workflow Cards 样品包：5 张卡，解决 agent 跑偏、工具误用、memory 混乱和长任务不可复盘的问题。

你愿意试读 10 分钟并告诉我：最近一次 agent 失败案例、哪张最有用、哪张最弱吗？如果方便，我发 Markdown。
```

### 模板 E：访谈邀请

```text
谢谢你愿意看样品包。如果你最近刚好遇到过 agent 失败案例，我想约 15 分钟聊一下：

1. 你当时想让 agent 完成什么？
2. 它在哪里开始偏离？
3. 你是怎么发现失败的？
4. 如果有一张卡能提前避免这个问题，它应该提醒你什么？

访谈不会推销，只用于判断完整 25 张卡应该优先写哪些主题。
```

## 7 天执行节奏

| 天数 | 动作 | 交付物 | 判断点 |
|---|---|---|---|
| Day 1 | 发给 3 位熟悉的开发者 | 3 条私信、样品包链接 | 是否有人愿意立即看 |
| Day 2 | 发到 1 个小社群或朋友圈 | 1 条短介绍 | 标题和痛点是否被理解 |
| Day 3 | 找 2 位工具/内容作者请教 | 2 条请教私信 | 是否认为有传播价值 |
| Day 4 | 整理前 3 天反馈 | 反馈表、问题列表 | 哪些卡最有用/最弱 |
| Day 5 | 根据反馈重写标题和 1 张卡 | v0.2 样品包 | 是否更具体 |
| Day 6 | 询问早鸟或完整包意向 | 3-5 条跟进 | 是否有人愿意付费/登记 |
| Day 7 | 决策 continue/narrow/stop | 决策记录 | 进入 25 张完整包或收窄到某类场景 |

## 本轮不要做

- 不要先做漂亮网站、封面、复杂排版。
- 不要一次性写完 25 张卡再验证。
- 不要泛泛问“你觉得怎么样”，必须问具体使用场景和愿不愿意推荐。
- 不要把反馈只记在聊天窗口里，必须沉淀到反馈记录表。
- 不要承诺团队版、课程或工具，除非至少 3 个目标读者主动提出类似需求。
