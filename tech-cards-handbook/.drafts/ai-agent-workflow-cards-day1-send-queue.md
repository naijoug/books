# AI Agent Workflow Cards Day 1 发送队列

> 用途：把 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-feedback-tracker.md` 中的前 3 个对象画像，拆成可以今天直接执行的发送顺序、模板选择和记录规则。这个文件不虚构真实反馈，也不替代联系人名单；它只帮助把 Day 1 从“想找人”推进到“知道先发哪 3 类消息、如何记录是否愿意试读”。

## Day 1 目标

- 发送前置询问给 3 位目标读者；
- 至少 2 位愿意接收 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-sample-pack-v0.1.md`；
- 每一次拒绝也记录原因，拒绝不算失败，无法归因才算失败；
- 不在没有反馈前修改样品包正文。

## 发送前检查

- [ ] 对方最近 30 天内确实用过 Cursor、Claude Code、Codex、ChatGPT coding、OpenClaw 或类似 coding agent；
- [ ] 能说出为什么找 TA，而不是群发；
- [ ] 消息中只请求 10 分钟试读和 4 个具体反馈问题；
- [ ] 先问是否愿意收 Markdown，不直接塞全文；
- [ ] 准备好把结果回填到 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-feedback-tracker.md`。

## 发送顺序

| 顺序 | 对象代号 | 必须满足的真实条件 | 渠道 | 使用模板 | 首句定制点 | 发送后立即记录 |
|---:|---|---|---|---|---|---|
| 1 | FAMILIAR-CODING-AGENT-USER | 熟人；最近用过 coding agent 写业务代码；能直接追问失败案例 | 私聊 | A | 提到 TA 最近使用的工具或项目类型 | 是否愿意试读、是否可在 24 小时内反馈 |
| 2 | TEAM-WORKFLOW-MAINTAINER | 关心团队规范、PR、交接或工具权限；可能不是重度内容消费者 | 私聊 | A + E | 强调“团队可复用工作流”，不是个人 prompt | 是否认为卡片适合团队规范化 |
| 3 | COMMUNITY-FAILURE-CASE | 在小社群/公开讨论里提过 agent 跑偏、误用工具、上下文丢失 | 小社群私聊 | B | 引用对方提过的具体失败模式 | 是否愿意补一个真实失败案例 |

## 可直接复制的 Day 1 消息

### 1. 熟人开发者

```text
我在做一个很小的验证：AI Agent Workflow Cards，目标是把“让 agent 写代码”从一次性 prompt 变成可运行、可复盘、可交接的工作流。

我想到你是因为你最近也在用 {tool_or_context}。现在只有 5 张免费样卡，主题包括工具描述、迭代上限、memory 分层、长任务心跳。

你愿意花 10 分钟看一版 Markdown 吗？我只想问 4 个问题：哪张最有用、哪张最没用、还缺什么、会不会推荐给别人。
```

### 2. 团队流程/规范维护者

```text
我在验证一份给程序员的 AI Agent Workflow Cards。它不是 prompt 合集，而是把 agent 工作流拆成可检查的卡片：边界、工具、记忆、停止条件、可复盘证据。

想到你是因为你更关心 {team_workflow_context}。我想知道这类卡片是否适合沉淀成团队规范，而不只是个人经验。

如果方便，我发你 5 张 Markdown 样卡。你只需要判断：哪张适合团队复用、哪张太个人化、还缺什么团队场景。
```

### 3. 社群失败案例跟进

```text
我看到你之前提到过 {specific_agent_failure}。我正在验证一份 AI Agent Workflow Cards 样品包，正好在拆这类失败：agent 跑偏、工具误用、memory 混乱、长任务不可复盘。

现在有 5 张 Markdown 样卡。你愿意看 10 分钟并告诉我：哪张最像你的真实问题、哪张没帮助、还缺哪类卡吗？
```

## 发送后记录格式

把以下块复制到反馈跟踪表的“下一步”或备注中：

```text
Day 1 contact note
- 对象代号：
- 发送时间：
- 使用模板：A / A+E / B
- 是否先问再发：是 / 否
- 对方是否愿意试读：是 / 否 / 待回复
- 如果拒绝，拒绝原因：没时间 / 不用 agent / 不感兴趣 / 其他
- 样品包是否发出：是 / 否
- 约定反馈时间：
- 下一步：发送样品包 / 24h 后轻提醒 / 停止跟进
```

## 24 小时轻提醒

只提醒一次；如果对方未回复，不继续追。模板：

```text
轻提醒一下：如果这周没时间看完全没关系。我主要想验证这个方向是否真实有用；如果你愿意，只回复一句“最想解决的 agent 失败场景”也很有帮助。
```

## Day 1 结束判断

| 结果 | 下一步 |
|---|---|
| 3 人中至少 2 人愿意试读 | 发出样品包，并在 Day 2 前等待具体反馈 |
| 只有 1 人愿意试读 | Day 2 继续找更窄的人群，不改样品包正文 |
| 0 人愿意试读，但拒绝原因集中在“没时间” | 缩短开场消息，保留同一定位 |
| 0 人愿意试读，且拒绝原因集中在“不懂解决什么” | 按 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-v0.2-revision-rules.md` 只重写一句话定位 |
| 收到具体失败案例 | 先记录到反馈跟踪表；Day 4 再归类，不立刻改卡 |

## 不做事项

- 不把对象代号伪装成真实联系人；
- 不写“用户反馈说……”除非真的收到回复；
- 不为了提高回复率承诺免费定制、课程或工具；
- 不在 Day 1 结束前新增第 6 张样卡；
- 不把样品包直接群发到大群。
