# AI Agent Workflow Cards v0.2 修订规则

> 用途：在没有真实反馈前，避免凭空“优化”样品包；在拿到反馈后，把 `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-sample-pack-v0.1.md` 的改动限制在可解释、可回滚、可验证的范围内。

## 修订前提

v0.2 只能在满足以下任一条件后开始：

1. `books/tech-cards-handbook/.drafts/ai-agent-workflow-cards-feedback-tracker.md` 中至少记录 3 条有效反馈；
2. 至少 2 位目标读者指出同一个定位问题、同一张弱卡，或同一种缺失场景；
3. Day 1-3 外联连续无人愿意试读，需要先重写开场标题，而不是重写整包内容。

如果没有满足以上条件，本轮只能继续外联、补记录表或改进发送顺序；不要改样品包正文。

## 有效反馈定义

一条有效反馈至少包含 3 个字段：

- 反馈者类型：例如熟人程序员、团队流程负责人、独立开发者、内容作者；
- 真实场景：最近一次使用 Cursor、Claude Code、Codex 或其他 coding agent 时遇到的具体失败；
- 可行动判断：最有用卡片、最弱卡片、缺失卡片、推荐形式、愿不愿意转发或留下早鸟意向中的至少一项。

以下反馈不计入 v0.2 决策：

- “不错”“挺有意思”“收藏了”但没有具体场景；
- 只评价排版或语气，没有说明是否解决 agent 工作流问题；
- 来自没有使用过 coding agent 的泛 AI 兴趣读者。

## v0.2 可改范围

| 改动类型 | 是否允许 | 触发条件 | 验证方式 |
|---|---|---|---|
| 重写一句话定位 | 允许 | 2 人无法复述样品包解决什么问题 | 新标题能被 1 位目标读者用自己的话复述 |
| 调整 5 张样卡排序 | 允许 | 最有用卡片集中在后半部分 | 把高频有用卡前移，并记录原因 |
| 重写 1 张弱卡 | 允许 | 同一张卡被 2 人认为太基础/太抽象 | 增加真实失败场景和检查步骤 |
| 新增 1 张替换卡 | 谨慎允许 | 2 条以上反馈指向同一缺失场景 | 替换最弱卡，不把样品包扩到 6 张以上 |
| 改交付形式 | 谨慎允许 | 反馈明确偏好 PDF / Notion / Web | 只做最小格式转换，不做完整网站 |
| 扩写到 25 张完整包 | 不允许 | 需要 Day 7 continue 决策后再做 | 先写大纲和 3 张最被要求的卡 |

## 反馈到修订的映射

| 反馈信号 | v0.2 动作 | 不要做 |
|---|---|---|
| “像 prompt 合集” | 标题改成“工作流卡片”，强调边界、停止条件、可复盘证据 | 增加更多 prompt 模板 |
| “太基础” | 给对应卡补真实失败前后对比 | 直接删掉基础卡，导致新手读不懂 |
| “不知道什么时候用” | 每张卡开头补适用任务场景 | 增加抽象理论解释 |
| “团队落地更有用” | 增加团队 checklist 或 PR review 场景 | 立刻做企业版服务页 |
| “想要可打印/Notion” | 做一个最小 PDF/Notion 版本 | 先搭建完整销售网站 |
| “最关心工具失败和验收” | 把失败出口、工具结果可观察、验收证据前移 | 一次性重排全部章节 |

## 等待反馈期间的检查清单

如果下一轮仍没有真实外联反馈，优先做这些不虚构用户声音的小事：

- [ ] 把反馈跟踪表中的 10 个对象画像替换成实际可联系的对象代号；
- [ ] 给每个对象选择一个开场模板和发送渠道；
- [ ] 记录“是否愿意试读”，即使对方拒绝也记录原因；
- [ ] 只修正错别字、链接、来源路径等客观问题；
- [ ] 不新增“用户最想要”的结论，除非来自真实反馈。

## Day 7 决策门槛

- **continue**：至少 5 条有效反馈，2 个以上愿意转发/留下邮箱/询问完整包；
- **narrow**：反馈集中在单一人群或单一场景，例如团队规范、独立开发、agent 调试；
- **stop**：有效反馈少于 2 条，或读者只愿意收藏免费内容，没有任何具体痛点或后续意向。

v0.2 的目标不是“更完整”，而是让下一轮验证更容易得到具体反馈。
