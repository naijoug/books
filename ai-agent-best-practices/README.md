# AI Agent 最佳实践指南

> 从概念到生产：构建智能、可靠、可扩展的 AI Agent 系统。

## 书籍定位

这是一本面向开发者、技术负责人和 AI 应用构建者的 Agent 工程实践指南。它不只介绍 Agent 概念，也覆盖设计原则、单 Agent 与多 Agent 架构、记忆系统、工具集成、测试调试、部署监控和安全伦理。

## 第十章收口导读

第十章已经从“风险提醒”扩展为一套可上线的安全控制链：先识别 Agent 能行动带来的主要风险，再用工具风险等级、工具网关中的服务端权限策略、Prompt 注入防御、数据分类脱敏、人工确认、脱敏执行 trace、审计日志、事故熔断 runbook 和发布门禁串成闭环。

准备把 Agent 从原型推向生产时，可以按下面顺序使用本书后半部分：

1. 先读第 7 章，梳理工具注册、工具描述、执行沙箱、工具路由和供安全回归/发布门禁使用的工具安全元数据。
2. 再读第 8 章，建立 Golden Tasks、权限测试、离线评估、敏感字段扫描和可复用的安全回归集，并把 `release_id`、`safe_trace_links`、`audit_event_ids` 等评估报告字段固化为后续章节可复用的交接格式。
3. 接着读第 9 章，准备部署形态、监控指标、告警、灰度与回滚，并把第 8 章评估报告中的失败样本、脱敏执行 trace 和审计事件接入发布报告。
4. 最后读第 10 章，把权限、数据、审批、审计日志、事故熔断 runbook 和伦理边界固化为上线门禁，让安全门禁报告可以直接引用第 8 章产出的评估证据。

## 90 分钟上线前审查工作流

如果读者已经有一个可运行的 Agent 原型，不必从头重读全书。可以把第 7-10 章压缩成一次 90 分钟审查，用来判断“今天能不能灰度”：

| 时间盒 | 动作 | 产出 |
|---|---|---|
| 0-20 分钟 | 按第 7 章列出所有工具，标注读/写、风险等级、owner、回滚方式和默认 allow/deny 策略 | 一张工具风险表；没有 owner 或回滚说明的工具暂不进生产 allowlist |
| 20-40 分钟 | 按第 8 章挑 10-20 个 Golden Tasks，覆盖成功路径、失败路径、越权工具、Prompt 注入和敏感字段泄露 | 一份可重跑的评估输入集，安全样本失败默认阻断发布 |
| 40-60 分钟 | 按第 9 章确认灰度、监控、预算、回滚、发布报告字段和告警负责人 | 一份发布报告草稿，至少包含 `release_id`、模型/Prompt 版本、失败样本和回滚条件 |
| 60-80 分钟 | 按第 10 章检查工具网关、审批、脱敏执行 trace、审计日志和事故熔断 runbook | 一份安全门禁结论，明确 `pass`、`warn` 或 `block` |
| 80-90 分钟 | 汇总仍未满足的条件，决定只读灰度、人工接管灰度或推迟上线 | 一个可追责的上线决定，而不是“感觉差不多” |

这张工作流的重点不是制造更多文档，而是把上线讨论变成证据链：工具风险表说明“能做什么”，Golden Tasks 说明“测过什么”，发布报告说明“如何观测和回滚”，安全门禁说明“哪些风险仍不可接受”。如果 90 分钟内无法填出这些最小产物，就说明系统还停留在演示原型，不应该开放高风险写操作。
