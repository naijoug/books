# AI Agent 最佳实践指南

## 第二章：Agent 设计原则 —— 构建优秀 Agent 的核心法则

> "设计一个好的 Agent，不是看它能做多少事，而是看它如何优雅地处理它做不到的事。"

---

## 2.1 好 Agent 的 5 个核心特征

### 🎯 特征 1：目标明确且可度量

**反面教材**：
```
❌ "帮我处理一下这个文档"
   - 什么叫"处理"？
   - 处理到什么程度算完成？
   - 如何判断成功还是失败？
```

**正面教材**：
```
✅ "将这个 PDF 文档中的表格提取出来，保存为 CSV 格式，
   并确保每列的数据类型正确，然后邮件发送给我"
   - 明确的输入输出
   - 可验证的完成标准
   - 清晰的步骤
```

**设计原则**：
- 每个任务都要有明确的"完成定义"（Definition of Done）
- 提供成功/失败的判断标准
- 尽量量化指标（时间、质量、格式等）

---

### 🛡️ 特征 2：边界清晰且安全可控

**Agent 不是万能的，知道自己的边界比能力更重要！**

#### 安全边界示例

```python
# 工具定义时明确边界
tools = [
    Tool(
        name="RunPython",
        func=safe_python_exec,
        description="""
        运行 Python 代码，但有以下限制：
        - 不能访问网络
        - 不能读写文件系统
        - 执行时间不能超过 30 秒
        - 不能导入 os, sys, subprocess 等危险模块
        """
    )
]
```

#### 优雅降级机制

```
当 Agent 遇到不确定的情况时：
1. 识别自己的能力边界
2. 寻求用户确认，而不是猜测
3. 提供选项，让用户做选择
4. 明确说明风险和限制

❌ 错误："我不确定，但我试试..."
✅ 正确："这涉及到修改生产数据，有两个选项：
   A) 我先在测试环境验证给你看
   B) 你确认后我再执行
   你选哪个？"
```

### 🧠 特征 3：有记忆且会学习

#### 记忆分层设计

| 记忆类型 | 作用 | 存储方式 | 保留时长 |
|----------|------|----------|----------|
| **瞬时记忆** | 当前思考过程 | Prompt 上下文 | 单次请求 |
| **工作记忆** | 会话上下文 | 短期存储 | 本次会话 |
| **长期记忆** | 用户偏好、历史经验 | 向量数据库 | 永久 |
| **情景记忆** | 关键事件回顾 | 结构化存储 | 永久 |

#### 记忆使用最佳实践

### 🔄 特征 4：可观察且可调试

#### 结构化思考日志

```
🤔 思考: 用户让我订机票，我需要：
   1. 先问清楚时间和目的地
   2. 搜索可用航班
   3. 比较价格和时间
   4. 推荐选项

💬 提问: 请问你想什么时候出发，去哪里？

[用户回复: 下周去北京]

🤔 思考: 知道了，下周去北京。需要确认：
   - 具体是哪一天？
   - 有偏好的航空公司吗？
   - 预算范围？

💬 提问: 好的！还想确认几个细节：
   1. 下周具体是周一到周五哪一天？
   2. 有偏好的时间段（早中晚）吗？
   3. 预算大概在什么范围？
```

#### 可观测性设计

| 指标 | 说明 | 收集方式 |
|------|------|----------|
| 任务成功率 | 完成的任务占比 | 任务状态标签 |
| 平均步骤数 | 完成任务平均用多少步 | 步骤计数 |
| 工具使用率 | 每个工具被调用的频率 | 工具调用日志 |
| 纠错次数 | 从错误中恢复的次数 | 错误日志 |
| 用户满意度 | 用户反馈评分 | 显式/隐式反馈 |

### 👥 特征 5：人机协作而非取代

**好的 Agent 是增强人类能力，而不是替代人类！**

#### 协作模式设计

```
模式 1: Agent 提议，人类决定
   - Agent 分析情况，给出 3 个选项
   - 人类选择其中一个
   - Agent 执行

模式 2: 人类指导，Agent 执行
   - 人类给出高层次指示
   - Agent 拆解并执行
   - 遇到不确定时立即停下来确认

模式 3: Agent 执行，人类监督
   - Agent 自主执行
   - 实时显示进度和思考
   - 人类随时可以中断或调整
```

## 2.2 Agent 设计的 10 条最佳实践

### 实践 1：从简单开始，逐步迭代

```
❌ 错误做法：
   第一天就想做一个全能 Agent，会写代码、会设计、会管理...

✅ 正确做法：
   v1.0: 只能回答问题，不能调用任何工具
   v1.1: 增加搜索工具
   v1.2: 增加文件读写工具
   v2.0: 增加多步规划能力
   ...
   逐步进化！
```

### 实践 2：给工具清晰且精确的描述

```
❌ 不好的描述：
   "搜索工具"

✅ 好的描述：
   "当你需要回答关于 2023 年之后的时事问题、
   查询最新的产品价格、或获取你不知道的事实信息时，
   使用这个工具。输入应该是具体的搜索关键词。"
```

### 实践 3：限制工具数量（开始时 ≤ 5 个）

**原因**：
- 工具太多 → Agent 选择困难
- 工具太多 → 调试困难
- 工具太多 → 注意力分散

**建议**：
- v1.0: 2-3 个最核心的工具
- 每个版本增加 1-2 个工具
- 定期评估，删除不用的工具

### 实践 4：优雅的错误处理和恢复

```python
# 设计重试策略
async def execute_with_retry(agent, task, max_retries=3):
    last_error = None
    
    for attempt in range(max_retries):
        try:
            return await agent.run(task)
        except Exception as e:
            last_error = e
            
            if attempt < max_retries - 1:
                # 让 Agent 反思错误
                reflection = await agent.reflect(
                    f"刚才失败了，错误是: {e}\n如何改进？"
                )
                # 根据反思调整策略
                agent.adjust_strategy(reflection)
    
    raise last_error
```

### 实践 5：提供明确的"停止"信号

**Agent 需要知道什么时候停下来**：
- 任务完成时
- 无法继续时
- 需要用户输入时
- 达到最大步数时
- 成本超过阈值时

### 实践 6：使用思维链（Chain-of-Thought）

```
❌ 直接输出：
   "答案是 42"

✅ 思维链输出：
   "让我想想这个问题...
   首先，我需要理解题目问的是什么...
   然后，我应该考虑这几个方面...
   基于以上分析，我的答案是 42"
```

### 实践 7：为不同场景设计不同的 Prompt

| 场景 | Prompt 重点 |
|------|------------|
| **创意任务** | 鼓励多样性，减少限制 |
| **精确任务** | 强调准确性，要求验证 |
| **学习任务** | 要求解释思考过程 |
| **紧急任务** | 限制选项，快速决策 |

### 实践 8：记录一切，便于分析

**应该记录的数据**：
- 完整的输入输出
- Agent 的思考过程
- 工具调用和返回
- 用户反馈
- 错误和恢复
- 耗时和成本

### 实践 9：建立评估体系，持续优化

**评估维度**：
1. 效果（任务完成质量）
2. 效率（时间、步数、成本）
3. 用户体验（流畅度、满意度）
4. 可靠性（错误率、恢复能力）

### 实践 10：考虑伦理和社会影响

**自问这些问题**：
- 这个 Agent 可能被滥用吗？
- 它会产生偏见或不公平的结果吗？
- 用户的数据安全和隐私有保障吗？
- 出现错误时，责任如何界定？

## 2.3 避免这些常见陷阱

### ❌ 陷阱 1：过度承诺

```
❌ 错误："我们的 Agent 能解决所有问题！"

✅ 正确："我们的 Agent 在这些场景下表现很好：
   [场景列表]
   在这些情况下需要人工介入：
   [边界说明]"
```

### ❌ 陷阱 2：没有人工退出机制

**确保**：
- 用户随时可以中断
- Agent 遇到不确定时会停下来
- 有明确的"移交"给人类的流程

### ❌ 陷阱 3：忽略边缘情况

**测试这些场景**：
- 用户输入完全不相关的内容
- 工具返回错误或超时
- 网络中断
- 权限不足
- 数据格式异常
