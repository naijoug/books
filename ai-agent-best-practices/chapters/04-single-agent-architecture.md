# AI Agent 最佳实践指南

## 第四章：单 Agent 架构模式 —— 从 ReAct 到更复杂的设计

> "一个好的架构不是一开始就完美的，而是随着需求演变得越来越好的。"

---

## 4.1 最简单的 Agent：ReAct 模式

### 4.1.1 ReAct 是什么？

ReAct（Reasoning + Acting）是最简单也最经典的 Agent 架构模式。

**核心思想**：
- 思考（Reasoning）→ 行动（Acting）→ 观察（Observing）→ 循环

```
用户输入
    ↓
[ 思考 ] → 我需要做什么？
    ↓
[ 行动 ] → 调用工具
    ↓
[ 观察 ] → 获取工具结果
    ↓
[ 思考 ] → 根据结果，下一步做什么？
    ↓
(循环直到完成)
    ↓
最终答案
```

### 4.1.2 ReAct 的 Prompt 模板

```
Answer the following questions as best you can. You have access to the following tools:

{tools}

Use the following format:

Question: the input question you must answer
Thought: you should always think about what to do
Action: the action to take, should be one of [{tool_names}]
Action Input: the input to the action
Observation: the result of the action
... (this Thought/Action/Action Input/Observation can repeat N times)
Thought: I now know the final answer
Final Answer: the final answer to the original input question

Begin!

Question: {input}
Thought:{agent_scratchpad}
```

### 4.1.3 ReAct 的优缺点

| 优点 | 缺点 |
|------|------|
| ✅ 简单易懂 | ❌ 可能陷入循环 |
| ✅ 易于实现 | ❌ 没有长期记忆 |
| ✅ 可解释性强 | ❌ 复杂任务可能需要很多步 |
| ✅ 适合大多数场景 | ❌ 没有反思和调整能力 |

## 4.2 ReAct 的改进：添加反思

### 4.2.1 ReAct + Reflection 模式

在 ReAct 的基础上，添加一个反思步骤：

```
用户输入
    ↓
[ 思考 ] → 我需要做什么？
    ↓
[ 行动 ] → 调用工具
    ↓
[ 观察 ] → 获取工具结果
    ↓
[ 反思 ] → 这个结果好吗？需要调整吗？
    ↓
[ 思考 ] → 根据反思，下一步做什么？
    ↓
(循环直到完成)
```

### 4.2.2 反思的 Prompt 示例

```
反思步骤：
1. 刚才的行动结果符合预期吗？
2. 有没有错误或意外的情况？
3. 我需要调整策略吗？
4. 有没有更好的方法？

基于以上反思，决定下一步行动。
```

## 4.3 更复杂的架构：Plan-and-Execute

### 4.3.1 什么是 Plan-and-Execute？

将任务分为两个阶段：

```
用户输入
    ↓
[ 规划阶段 ] → 制定详细的执行计划
    ↓
[ 执行阶段 ] → 一步步执行计划
    ↓
    ↓ (如果需要，重新规划)
    ↓
最终答案
```

### 4.3.2 规划阶段的 Prompt

```
你是一个规划专家。给定一个任务，请制定一个详细的执行计划。

任务：{task}

请按以下格式输出计划：
1. 第一步：...
2. 第二步：...
3. 第三步：...
...

每个步骤应该具体、可执行。
```

### 4.3.3 Plan-and-Execute 的优缺点

| 优点 | 缺点 |
|------|------|
| ✅ 更适合复杂任务 | ❌ 规划可能不准确 |
| ✅ 更好的可预测性 | ❌ 需要更多调用 |
| ✅ 可以中途调整计划 | ❌ 实现更复杂 |

## 4.4 记忆增强的 Agent

### 4.4.1 记忆的分层设计

```
┌─────────────────────────────────────┐
│   瞬时记忆 (Working Memory)        │
│   - 当前思考过程                    │
│   - 会话上下文                      │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│   工作记忆 (Short-term Memory)      │
│   - 当前任务相关信息                │
└──────────────┬──────────────────────┘
               │
┌──────────────▼──────────────────────┐
│   长期记忆 (Long-term Memory)       │
│   - 用户偏好                        │
│   - 历史经验                        │
│   - 知识库                          │
└─────────────────────────────────────┘
```

### 4.4.2 记忆检索策略

不是所有记忆都有用！好的检索策略：

1. **相似度检索**：向量相似度
2. **时间衰减**：近期的记忆更重要
3. **重要性权重**：用户标记的优先
4. **上下文相关性**：与当前任务相关的

## 4.6 本章小结

✅ **学习要点**：
1. ReAct 是最简单也最经典的模式（思考 → 行动 → 观察 → 循环）
2. 添加反思可以改进 ReAct
3. Plan-and-Execute 适合复杂任务（先规划，再执行）
4. 记忆系统要分层设计，检索策略很重要
5. 完整架构：接口层 + 编排层 + 推理层 + 记忆层 + 工具层
