# AI Agent 最佳实践指南

## 第六章：记忆系统设计 —— 让 Agent 记住重要的事

> "没有记忆的 Agent 就像金鱼，每次对话都是新的开始。"

---

## 6.1 记忆系统的重要性

### 6.1.1 为什么需要记忆？

```
没有记忆的对话：
用户: 我叫小明
Agent: 你好小明！
用户: 我今天生日
Agent: 生日快乐！
用户: 我叫什么？
Agent: 我不知道... 😅

有记忆的对话：
用户: 我叫小明
Agent: [记住了: 名字=小明]
用户: 我今天生日
Agent: [记住了: 生日=今天]
用户: 我叫什么？
Agent: 你叫小明，而且今天是你生日！🎂
```

### 6.1.2 好的记忆系统的特征

| 特征 | 说明 |
|------|------|
| 持久性 | 记忆不会轻易丢失 |
| 可检索 | 需要时能快速找到 |
| 相关性 | 只检索相关的记忆 |
| 可更新 | 能添加、修改、删除记忆 |
| 可遗忘 | 不重要的记忆能被移除 |

## 6.2 记忆的分层架构

### 6.2.1 经典分层模型

```
┌─────────────────────────────────────────────────┐
│  瞬时记忆 (Sensory Memory)                    │
│  - 持续时间：几秒                              │
│  - 容量：非常有限                              │
│  - 用途：当前输入的原始感知                    │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│  短期记忆 (Short-term Memory)               │
│  - 持续时间：几分钟到几小时                  │
│  - 容量：有限（约 4-7 个项目）               │
│  - 用途：当前任务的上下文                    │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│  长期记忆 (Long-term Memory)                │
│  - 持续时间：永久                            │
│  - 容量：几乎无限                            │
│  - 用途：用户偏好、历史经验、知识库          │
└─────────────────────────────────────────────────┘
```

### 6.2.2 每种记忆的用途

**瞬时记忆**：
- 当前用户输入
- 工具的原始输出
- 上一个思考步骤

**短期记忆**：
- 当前会话的对话历史
- 当前任务的中间结果
- 正在处理的文档内容

**长期记忆**：
- 用户的个人偏好
- 历史对话总结
- 领域知识库
- 成功/失败的经验

## 6.3 记忆的存储方式

### 6.3.1 向量数据库（Vector Database）

**原理**：
- 将文本转换为向量（Embeddings）
- 相似度搜索找到相关记忆
- 支持语义检索

**适用场景**：
- 大量文本记忆
- 语义相似度检索
- 模糊匹配

**常用数据库**：
- Pinecone（托管）
- Weaviate（自托管/托管）
- Milvus（自托管/托管）
- Chroma（本地/自托管）

**示例代码**：
```python
from langchain.vectorstores import Chroma
from langchain.embeddings import OpenAIEmbeddings

# 创建向量存储
embeddings = OpenAIEmbeddings()
vectorstore = Chroma(embedding_function=embeddings)

# 添加记忆
vectorstore.add_texts([
    "用户喜欢深色模式",
    "用户的生日是 3 月 15 日",
    "用户喜欢简洁的设计"
])

# 检索相关记忆
results = vectorstore.similarity_search(
    "用户的偏好是什么？",
    k=2
)
```

### 6.3.2 图数据库（Graph Database）

**原理**：
- 用节点和边存储知识
- 适合存储关系和结构
- 支持复杂查询

**适用场景**：
- 知识图谱
- 实体关系
- 复杂推理

**常用数据库**：
- Neo4j
- ArangoDB
- NebulaGraph

### 6.3.3 传统数据库

**原理**：
- 结构化存储
- SQL 查询
- 事务支持

**适用场景**：
- 用户配置
- 对话日志
- 结构化数据

**常用数据库**：
- PostgreSQL
- SQLite
- MySQL

## 6.4 记忆检索策略

### 6.4.1 不仅仅是相似度搜索

**问题**：
- 最近的记忆不一定最相关
- 重要的记忆可能被淹没
- 时间久了会遗忘重要的事

**更好的策略**：

```python
def retrieve_memories(query, k=5):
    # 1. 相似度检索
    similar = vectorstore.similarity_search(query, k=k*2)
    
    # 2. 时间衰减
    results = []
    for mem in similar:
        # 越新的记忆权重越高
        time_score = calculate_time_decay(mem.timestamp)
        
        # 3. 重要性权重
        importance_score = mem.importance
        
        # 4. 综合评分
        total_score = (
            mem.similarity_score * 0.5 +
            time_score * 0.3 +
            importance_score * 0.2
        )
        
        results.append((mem, total_score))
    
    # 5. 重新排序
    results.sort(key=lambda x: x[1], reverse=True)
    
    return [mem for mem, score in results[:k]]
```

### 6.4.2 记忆的重要性评分

**如何判断记忆的重要性？**

1. **用户标记**：
   - 用户明确说"记住这个"
   - 用户反复提及

2. **频率统计**：
   - 被提及的次数
   - 被检索的次数

3. **内容分析**：
   - 是否包含个人信息
   - 是否包含关键决策
   - 是否包含错误教训

## 6.5 记忆的更新与维护

### 6.5.1 记忆的生命周期

```
创建 → 存储 → 检索 → 更新 → 遗忘
  ↓                        ↓
  └─────── 评估重要性 ────┘
```

### 6.5.2 何时更新记忆？

1. **用户明确纠正**：
   - "不对，我说的是 X 不是 Y"

2. **新信息更准确**：
   - 旧信息过时了
   - 新信息更完整

3. **合并相关记忆**：
   - 同一主题的多个记忆
   - 可以合并成更完整的记忆

### 6.5.3 何时遗忘记忆？

1. **时间太久**：
   - 超过一定时间没被访问
   - 信息可能过时

2. **不重要**：
   - 重要性评分低
   - 从未被检索过

3. **重复冗余**：
   - 有更新更准确的版本
   - 可以删除旧版本
