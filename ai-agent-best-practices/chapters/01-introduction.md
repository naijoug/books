# AI Agent 最佳实践指南

## 第一章：AI Agent 入门 —— 理解基础概念

> "AI Agent 是下一代人机交互范式 —— 它们不是被动响应的工具，而是主动思考、行动、学习的数字助手。"

---

### 1.1 什么是 AI Agent？

**AI Agent 的定义**：

AI Agent 是一个能够感知环境、做出决策、并执行行动的自主系统。与传统的 chatbot 不同，Agent 具有以下核心特征：

| 特征 | 说明 |
|------|------|
| 🧠 **自主性** | 能够独立思考并制定计划，不需要用户一步步指令 |
| 👁️ **感知能力** | 可以接收和理解环境信息（文本、图像、工具输出等） |
| 🛠️ **工具使用** | 能够调用外部工具（API、数据库、浏览器等） |
| 📝 **记忆系统** | 拥有短期和长期记忆，能够从历史中学习 |
| 🎯 **目标导向** | 围绕明确目标展开行动，不断评估进展 |

**最简单的 Agent 架构**：

```
用户输入 → [ 思考 → 决策 → 行动 → 观察 ] → 循环直到完成
                ↑                        ↓
                └────── 记忆系统 ───────┘
```

---

### 1.2 Agent 与传统应用的区别

| 维度 | 传统应用 | AI Agent |
|------|----------|----------|
| **交互方式** | 预定义菜单/表单 | 自然语言对话 |
| **灵活性** | 固定流程 | 自适应路径 |
| **学习能力** | 需要代码更新 | 从交互中学习 |
| **工具集成** | 硬编码集成 | 动态工具选择 |
| **错误处理** | 预设错误码 | 推理恢复策略 |

**示例对比**：

传统应用预订机票：
```
1. 用户填写出发地、目的地、日期表单
2. 系统搜索固定选项
3. 用户点击确认
4. 完成
```

Agent 预订机票：
```
1. 用户说："帮我订下周去北京的机票，性价比高一点"
2. Agent 理解需求，询问预算和偏好
3. Agent 搜索多个平台，分析价格趋势
4. Agent 推荐 3 个选项并说明理由
5. 用户选择后，Agent 自动完成预订
6. Agent 发送确认信息，并提醒天气和交通
```

### 1.3 Agent 的核心组件

一个生产级的 AI Agent 通常包含以下组件：

#### 1.3.1 LLM 大脑（核心推理引擎）

**作用**：处理理解、推理、决策

**选型考虑**：
- 能力：选择当前可用的主流闭源模型或开源模型，不要把架构绑定到某一个模型版本
- 速度：实时交互 vs 后台任务
- 成本：预算约束
- 上下文窗口：需要处理多少历史信息

#### 1.3.2 记忆系统（Memory）

**类型**：
- **短期记忆**（Working Memory）：当前会话的上下文
- **长期记忆**（Long-term Memory）：历史交互、知识库
- **情景记忆**（Episodic Memory）：特定事件的详细记录

**实现方式**：
- 向量数据库（Pinecone, Weaviate, Milvus, Chroma）
- 图数据库（知识图谱）
- 传统数据库（PostgreSQL 等）
- 框架级记忆（如 LangGraph store、应用侧 profile store、任务日志等）

#### 1.3.3 工具集（Tools）

**常见工具类型**：
- 搜索：Google Search, Tavily, Bing
- 浏览：Playwright, Puppeteer
- 计算：Python REPL, Calculator
- 数据：SQL 数据库, API 调用
- 文件：读写文件, 代码执行
- 通信：邮件, Slack, 消息推送

**工具设计原则**：
- 单一职责：每个工具做一件事
- 清晰接口：明确的输入输出
- 错误处理：友好的失败反馈
- 安全沙箱：防止滥用

#### 1.3.4 规划模块（Planning）

**作用**：将复杂目标分解为可执行步骤

**常用策略**：
- **ReAct（Reasoning + Acting）**：思考 → 行动 → 观察，循环推进任务
- **思维链（Chain-of-Thought）**：一步步推理
- **Tree-of-Thought**：探索多个推理路径
- **反思（Reflection）**：回顾并改进
- **子目标分解**：将大任务拆分为小任务

#### 1.3.5 评估与反馈（Evaluation）

**关键指标**：
- 任务成功率
- 执行效率（步骤数、时间）
- 工具使用合理性
- 用户满意度
- 错误恢复能力

#### 1.3.6 安全与控制（Safety）

Agent 的能力来自“能调用工具”，风险也来自“能调用工具”。入门阶段就要建立三条底线：

- **最小权限**：默认只给读权限，高风险写操作必须单独授权。
- **人工确认**：涉及转账、发消息、删数据、改生产环境等动作时，必须让人确认。
- **可追溯**：记录用户输入、模型决策、工具参数、工具结果和最终输出，方便复盘与审计。

一个可靠的 Agent 不是“什么都能自动做”，而是“知道哪些事不能自动做”。

### 1.4 第一个简单的 Agent（代码示例）

让我们用 LangChain v1 风格构建一个最简单的 Agent。当前官方推荐使用 `create_agent` 作为高层入口，它底层运行在 LangGraph 之上，适合从最小示例起步。

```python
from langchain.agents import create_agent
from langchain.tools import tool


@tool
def search_ai_news(query: str) -> str:
    """搜索 AI 新闻。示例中返回固定结果；生产环境应接入真实搜索 API。"""
    return (
        "示例搜索结果："
        "1. 某模型发布新的工具调用能力；"
        "2. 某开源 Agent 框架更新了记忆模块；"
        "3. 某企业发布 AI 安全评估报告。"
    )


# 1. 创建 Agent
agent = create_agent(
    model="openai:gpt-5.4-mini",  # 替换为你账号可用的模型
    tools=[search_ai_news],
    system_prompt=(
        "你是一个谨慎的 AI 新闻助手。"
        "必须先调用工具获取信息，再用三条要点回答。"
    ),
)

# 2. 运行 Agent
result = agent.invoke({
    "messages": [
        {"role": "user", "content": "今天有什么值得关注的 AI 新闻？"}
    ]
})

print(result["messages"][-1].content)
```

**输出示例**：
```
今天有三件值得关注的 AI 新闻：

1. 某模型发布了新的工具调用能力，说明 Agent 正在从“聊天”走向“执行任务”。
2. 某开源 Agent 框架更新了记忆模块，开发者可以更方便地保存用户偏好和任务历史。
3. 某企业发布 AI 安全评估报告，提醒团队上线 Agent 前要做权限控制、审计日志和人工确认。
```
