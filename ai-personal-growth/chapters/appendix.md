## A.14 2026 年 AI 工作流体检表

> 适用场景：每周或每月复盘一次，判断自己是不是只是在“玩工具”，还是已经把 AI 变成稳定生产力。

| 维度 | 自查问题 | 合格标准 | 改进动作 |
|---|---|---|---|
| 高频任务 | 我是否列出了每周重复 3 次以上的任务？ | 至少 10 个任务进入清单 | 用「任务名称 / 输入 / 输出 / 判断标准」记录 |
| 工作流闭环 | AI 是否参与了从输入到交付的完整链路？ | 不只是聊天，而是能产出文档、代码、表格、邮件、复盘 | 给每个任务写一个 SOP |
| 人工判断 | 哪些环节必须由我决定？ | 关键决策、价值判断、对外承诺不交给 AI 自动决定 | 在模板中写明“人工确认点” |
| 事实来源 | 重要结论是否可追溯？ | 数据、法规、竞品、技术结论有来源或待确认标记 | 输出末尾加“事实核验表” |
| 权限边界 | Agent 能访问什么工具和数据？ | 默认最小权限，敏感操作二次确认 | 为每个 Agent 建权限清单 |
| 质量度量 | 我如何知道效率真的提升？ | 至少记录时间、返工次数、满意度三个指标 | 每周选 1 个流程做对比实验 |
| 资产沉淀 | 本次使用是否留下可复用资产？ | 形成模板、脚本、检查表、案例库中的至少一种 | 放入个人知识库或团队 Wiki |

### 一句话判断

如果一个 AI 工作流不能被复用、不能被审计、不能被你解释清楚，它就还不是生产力系统，只是一次性聊天。

## A.15 Agent 任务委派模板

2026 年之后，AI 的重点正在从“问答助手”转向“能调用工具、能分步骤执行、能维护上下文的 Agent”。委派任务时，不能只写“帮我做 X”，而要像给新人同事分配任务一样说明目标、权限、边界和验收标准。

```text
你是我的【任务型 Agent】。

任务目标：
【一句话描述最终要交付什么】

背景材料：
【粘贴相关资料、链接、文件路径或上下文】

可使用的工具/权限：
1. 可以读取：【文件/数据范围】
2. 可以修改：【文件/目录范围】
3. 可以联网搜索：【是/否，搜索主题】
4. 禁止操作：【删除文件/发送邮件/付款/发布内容/调用生产接口等】

执行流程：
1. 先列出你理解的任务和风险
2. 检查缺失信息；如果缺失不影响推进，请基于明确假设继续
3. 分步骤执行，每完成一个关键步骤就验证结果
4. 对高风险操作先输出建议，不要直接执行
5. 最后给出交付物、验证方式和未解决问题

验收标准：
- 输出必须包含：【格式要求】
- 事实必须标注来源或“待核验”
- 代码/脚本必须能运行，并说明测试命令
- 重要决策必须解释理由

失败处理：
如果工具失败或资料不足，请不要编造；请输出：
1. 已完成什么
2. 卡在哪里
3. 可替代方案
4. 我下一步应如何处理
```

### 使用提醒

- 给 Agent 的权限越大，检查点越要明确。
- 对“写文件、删文件、发消息、调用接口、花钱、影响他人”的动作，要默认设置人工确认。
- 对长期运行的 Agent，要定期查看日志，而不是只看最终结果。

## A.16 事实核验与来源标注表

> 适用场景：写文章、做方案、做职业规划、评估工具、引用报告数据时使用。

| 结论 | 来源 | 类型 | 可信度 | 是否需要二次核验 | 备注 |
|---|---|---|---|---|---|
| 例如：某报告认为组织级 AI 采用比个人试用更能产生稳定价值 | Microsoft Work Trend Index / Deloitte / McKinsey 等公开报告 | 行业研究 | 中-高 | 是 | 注意样本、地区、行业差异 |
| 例如：Agent 风险包括过度权限、提示注入、工具误用 | OWASP LLM / Agentic AI 安全资料、NIST AI RMF | 安全框架 | 高 | 是 | 落地时要结合具体系统 |
| 例如：某工具能提升 50% 效率 | 厂商宣传或单个案例 | 营销材料 | 低-中 | 必须 | 需要自己做小样本实验 |

### 核验提示词

```text
请帮我核验下面这段内容。

要求：
1. 把所有事实性陈述逐条列出
2. 区分“已给出来源”“需要外部核验”“只是观点”
3. 指出最可能误导读者的表述
4. 给出更稳妥的改写版本
5. 如果涉及数据，请提醒我检查样本、时间、地区和定义

内容：
【粘贴文本】
```

## A.18 个人 AI 使用红线清单

```text
我不会把以下事项完全交给 AI 自动决定：
1. 涉及法律、医疗、投资、重大职业选择的最终决策
2. 对他人的评价、处分、录用、裁撤等高影响判断
3. 未经授权处理他人的隐私、商业秘密或敏感数据
4. 未复核就发布带有事实、数据、引用、承诺的内容
5. 未理解代码影响就合并到生产环境
6. 未检查版权和授权就商用 AI 生成素材
7. 让 Agent 拥有超出任务需要的长期权限

我的默认做法：
- 低风险任务：AI 先做，我抽查
- 中风险任务：AI 辅助，我逐项复核
- 高风险任务：AI 只能提供参考，最终由人负责
```
